# 03 — Evaluation, Evidence and Authority

Evaluation protects the distinction between a persuasive proposal and an admissible epistemic update.

Core rules:

- generators/LLMs/tools may propose; they do not directly mint canonical authority;
- evidence identity and provenance remain addressable after supersession;
- negative/null/refuted/failed history is monotone;
- context and measurement contracts must be explicit;
- matched development improvement is not enough for a method promotion;
- fresh assurance must remain protected from adaptive reuse;
- the evaluator cannot be weakened by the challenger it evaluates.

The bootstrap will migrate RAKL's strongest authority, verification, benchmark and negative-history mechanics here only after each is mapped to the new recursive engine rather than copied wholesale.
