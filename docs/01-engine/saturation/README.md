# Mechanic bounded saturation

ORION separates a saturation **contract** from an observed saturation **receipt**.

For one mechanic, the Shadow V0 contract freezes a basis and requires at least two consecutive substantively flat rounds across registered coordinates:

- retained knowledge/evidence/assumptions/residuals;
- formulation (question, representation, decomposition, interfaces, measurement, evaluator);
- applicable route/source coverage;
- parent-domain growth;
- contradictions/obstructions/discriminators;
- fresh failure/experience patterns;
- method/operator frontier.

Closure additionally requires route-coverage, parent-domain/nearest-work, omission, freshness, evidence-lineage and processing-order audits where applicable.

A material reframe, newly relevant parent discipline, new failure variation, fresh contradiction, route implementation change, evidence-lineage change or post-cutoff work reopens the affected saturation receipt. Resource exhaustion with open obligations returns `CANNOT_CHECK_RESOURCE_BOUND`.

The contract explicitly represents `absolute_complete = false`. It is a stopping rule over a declared basis/cutoff, never a theorem that the world contains no unknown relevant knowledge.

The existing runtime `SaturateOperator` remains narrower until the richer route families and receipt/audit machinery have executable live-provider tests. Mechanic specification therefore must not silently tighten task-level solver defaults.
