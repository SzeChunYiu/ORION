# Development packet — issue #629 successor-conditioned scientific state

## Development question

Can ORION construct an exact bounded benchmark proving that **current-state equivalence does not imply future scientific-standing equivalence** after a later framework transition, without claiming novelty for sufficient statistics, bisimulation, event sourcing, dynamic assurance or epistemic-state replication?

The implementation is a research falsifier only. It does not authorize a runtime memory/state architecture.

## Atomic fibres

1. define a candidate-visible `CurrentSummary` that is exactly identical for both members of a delayed pair;
2. keep the differentiating history/lineage outside the current-summary baseline;
3. apply the **same** future transition to both pair members;
4. protect future-standing gold from current-summary policies;
5. implement DPAIR-1 evidence-route dependency debt;
6. implement DPAIR-2 negative-cause debt;
7. implement DPAIR-3 authority-origin debt;
8. prove a current-summary-only policy cannot distinguish both members of each pair;
9. implement a full-history baseline that can distinguish them;
10. implement a compact typed-state baseline containing exactly the registered load-bearing coordinates;
11. compare future-standing exactness independently from current task correctness;
12. keep all code research-local and expose tests through `tests/unit/research` only.

## Incumbent mechanics and negative history

- RSE-0 has frozen `INTERACTION_ONLY_RESIDUAL_FROZEN`; component novelty is struck.
- The RSSI pilot showed that individual parent rules fail but a simple donor union closes the first non-interaction families.
- A first transport/authority interaction makes naive union fail, but a coordinated donor policy can plausibly close it; it is therefore not yet an ORION-positive residual.
- Full event logs, ESR-style evidence+belief lineage, dynamic assurance/change-impact graphs, and policy/version receipts are mandatory comparators, not weak baselines.
- Standard sufficient-statistic and bisimulation theory already owns the mathematics of when a state summary preserves future-relevant distinctions.

The #629 atom therefore asks only whether the exact benchmark can expose a **future-science sufficiency ceiling** for a lossy current summary.

## Parent-domain recovery

The implementation explicitly treats these as parents:

- Bayesian/minimal sufficient state and predictive-state theory;
- epistemic simulation/bisimulation;
- dynamic epistemic logic and history-sensitive actions;
- event sourcing / deterministic replay;
- Epistemic State Replication (`L` immutable evidence log + `B` belief lineage);
- dynamic assurance and safety-evidence change impact;
- artifact-anchored verification memory;
- authorization bound to policy/schema/evaluator version.

A full-history parent is expected to pass the exact pair suite. That is a control result, not a failure of the benchmark.

## Saturation assessment

RSE-0 donor saturation reached two consecutive no-material-change rounds after dynamic-assurance and event-sourcing/authority-version rewordings. The residual is frozen at the interaction/recursive-generation level.

For this implementation atom, three delayed pair families are sufficient to test non-vacuity because they span three distinct scientific-standing causes:

- evidence applicability;
- negative-knowledge applicability;
- authority scope.

Do not add DPAIR-4/5 until the first three prove that the public/current-summary boundary is enforceable and the expected information ceiling is observable.

## Challenge to saturation basis

The benchmark could be fake if:

- pair membership leaks through IDs or ordering;
- the future transition differs between pair members;
- the current summary exposes the differentiating history field;
- a current-summary policy receives protected family/gold metadata;
- the full-history baseline is artificially handicapped;
- the typed state is simply the gold label under a renamed field;
- pair difficulty is created only by irrelevant noise;
- future standing is inferred from task answer rather than lineage.

Hostile tests must make current payloads byte-identical within each pair after removal of opaque case identity, and must verify future transition identity.

## Miss hypotheses

A stronger parent may still be hidden under:

- causal-state / predictive-state representation;
- proof-assistant context compression;
- assurance case modularization;
- incremental view maintenance;
- credential-chain continuity;
- database/event-sourcing snapshot sufficiency.

Those routes remain literature reopen triggers. They do not block an exact ceiling benchmark because the benchmark is designed to credit them if they preserve the needed distinction.

## Reopen triggers

Reopen this implementation packet if:

- a current-summary policy can infer pair membership from candidate-visible fields;
- the pair members are not truly current-observable equivalent;
- full-history reconstruction cannot achieve exact future standing;
- the typed-state baseline encodes protected gold rather than derivable lineage coordinates;
- the first three families reduce to one trivial surface heuristic;
- CI reveals cross-platform nondeterminism;
- a new donor makes the exact future-equivalence contract itself already benchmarked and fully matched.

## Frozen implementation hypothesis

A stdlib-only research module can generate DPAIR-1..3 such that:

```text
CurrentSummary(a) == CurrentSummary(b)
FutureTransition(a) == FutureTransition(b)
GoldFutureStanding(a) != GoldFutureStanding(b)
```

for every registered pair.

Expected non-vacuity results:

1. a deterministic current-summary-only policy must make at least one future-standing error in every pair;
2. a full-history policy must score 100% future-standing exactness;
3. a compact typed-state policy derived only from registered history coordinates must score 100%;
4. current task answer/standing remains identical across pair members;
5. public/current-summary serialization contains no hidden history or future gold;
6. deterministic regeneration is byte-identical for a fixed seed.

A pass establishes only that the benchmark exposes information loss relevant to future scientific standing. It does not establish ORION superiority over a full-history or donor-meta-product state.
