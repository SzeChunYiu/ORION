But a translation carries an obligation. Once the quantity has a name in the
donor field, the donor field's standard question applies to our committed
numbers, and it has never been asked here:

> **Is the committed syndrome minimal, or is it merely sufficient?**

`max_r6i_exact_rank2_shared_tag_dp` declares `STATES = 1024` — a 10-bit parity

state space is not a minimal one, and the difference is a factor this programme
has been quoting as though it were exact.

**This lane does not claim the number is wrong.** It claims the question was
never asked.

## 2. Q1 — the Nerode index, computed two ways that must agree

1. **Structurally.** Compute `r = rank_{F₂}(Σ)` by Gaussian elimination over the
   committed letter set. The subgroup ⟨Σ⟩ generated by the letters has order
   `2^r`, and for an abelian translation automaton with `t ∈ ⟨Σ⟩` the minimal
   DFA has exactly `2^r` states.
2. **Mechanically.** Build the reachable automaton explicitly and run
   **Moore/Hopcroft partition refinement** to a fixpoint. Report the block count.

**Both must be run and both must agree.** A single method agreeing with itself
is what this programme keeps catching. If they disagree, the terminal is the
`DISAGREEMENT` branch in §4 and neither number is reported as the answer.

## 3. Q2 — the consequence, stated exactly and not further

* If `2^r = 1024`: the committed state count **is** the Nerode index and every
  complexity statement resting on it stands as written. Report that plainly;
  a confirmation is a result.
* If `2^r < 1024`: the committed DP carries `1024 / 2^r` times more states than
  the feasibility language requires. State the factor. **Do not claim this makes
  anything faster**: the DP is min-plus and carries cost, and Nerode minimality
  is a statement about the *feasibility* language only. Whether the cost DP
  admits the same reduction is a separate question this lane does not answer and
  must not imply.
