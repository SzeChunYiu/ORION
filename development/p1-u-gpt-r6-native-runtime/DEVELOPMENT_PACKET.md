## Native root execution

For each episode, R6 instantiates canonical `OrionRuntime.from_providers(...)` with repository providers and a frozen deterministic semantic host. The root problem receives only the candidate-visible dossier.

The frozen root host intentionally begins without a retrieved verified claim so native DETECT exposes a material evidence residual. Native DIAGNOSE receives the dossier through the normal `LLMResearchReasoner` request and returns at most two **native `Responsibility` enum values**. It never emits a P1 evaluator gold label.

Every root candidate row must contain a real trace with at least:

- `FRAME.v1`;
- `SEARCH.v1`;
- `ABSORB.v1`;
- `RECONSTRUCT.v1`;
- `DETECT.v1`;
- `DIAGNOSE.v1`.

Unsafe/ambiguous native REFRAME may block; that is evidence, not a test failure.

## Frozen deterministic provider

The primary controller host uses repository `CallableLLMProvider`, `InMemoryRetrievalProvider`, and `InMemoryVerificationProvider`.

Root diagnosis always retains native `EVIDENCE` as a lower-level hypothesis and may add one surface-supported alternative chosen by a frozen keyword table from:

- `SEARCH`;
- `REPRESENTATION`;
- `EXECUTION`;
- `MEASUREMENT`;
- `METHOD`;
- `QUESTION`.

The same provider is used for `ORION_NATIVE_BASE` and `ORION_NATIVE_ARD`. Pair role, source class, source ID, evaluator gold and hidden probe values are never supplied to it.

This deterministic provider is a controller-isolation host, not a claim that semantic reasoning is solved. A positive primary still requires the changed-host replication specified in #723.

## ORION_NATIVE_BASE

The base arm runs the canonical root runtime and then translates its **native diagnosis output** into the coarser P1 responsibility families. A unique mapped family is assessed with native `ResponsibilityHypothesis` / `assess_responsibility`; more than one mapped family remains native `AMBIGUOUS` and the P1 decision is `UNRESOLVED`.

No active discriminator is acquired in this arm.

## Experimental native ARD

`ORION_NATIVE_ARD` starts from the same root runtime and the same mapped native diagnosis candidates, plus a `NO_HIGH_LEVEL_REFORMULATION` / keep-current hypothesis.

It may acquire at most two discriminators. Priority is frozen from narrower/lower-level toward broader revision responsibility:

1. SEARCH_OR_EVIDENCE;
2. REPRESENTATION_OR_INTERFACE;
3. IMPLEMENTATION_OR_ENVIRONMENT;
4. MEASUREMENT_OR_EVALUATOR;
5. OBJECTIVE_OR_MODEL_CLASS;
6. PROBLEM_BOUNDARY.

Each discriminator acquisition is itself a **child `OrionRuntime.solve` execution**. The evaluator host exposes only the selected discriminator's encoded source-grounded observation through an in-memory retrieval item. The item must be absorbed and independently accepted by `InMemoryVerificationProvider`; the controller reads the observation back from the returned runtime evidence state, not directly from the hidden probe mapping.

After each child solve, the surviving P1 hypotheses are represented by native `ResponsibilityHypothesis` objects and updated with native `assess_responsibility`. `INCONCLUSIVE` preserves ambiguity. No posterior or parallel authority system is allowed.
