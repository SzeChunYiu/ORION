## Development question

Can ORION-Q build a single typed quantum-research substrate that faithfully absorbs the strongest specialist discovery mechanisms and then demonstrates cross-domain research-state value before any P10 method-language expansion is attempted?

The maximal programme target remains:

`problem -> representation -> access/interface -> method language -> algorithm/research action -> verifier/resource closure -> authority`

with specialist donor systems treated as incumbent capabilities, not external competitors.

## Atomic questions

Q1. Can heterogeneous donor capabilities be represented with one minimal capability contract without erasing load-bearing domain assumptions?

Q2. Can one `QuantumResearchState` represent failure/reopening, access, resource, verifier and authority state across at least four materially different quantum research domains?

Q3. Does scoped failure provenance provide held-out decision value across domain boundaries, rather than only inside the earlier QC2/N1-C synthetic world?

Q4. Can a donor-composed controller using all known specialist capabilities close the benchmark without P10? If yes, that is the incumbent and P10 gets no credit.

Q5. What exact residual remains after the donor-composed controller receives the same visible state and tool budget?

Q6. Does any apparent ORION advantage vanish when the strongest current adaptive/agentic quantum mechanisms are composed faithfully?

### Current saturation statement

Saturation is sufficient only for a first donor-super-system protocol. It is not a novelty certificate. A newly found system that already jointly owns cross-domain research-state transfer + method-language edits + proof/resource authority reopens this packet.

## Challenge to the saturation basis

The search could be falsely flat because the literature is siloed by quantum subdomain. A system may perform a structurally equivalent operation under another vocabulary:

- meta-learning / algorithm portfolios;
- active experimental design / value of information;
- program-language/library induction;
- compiler IR/refinement;
- formal proof repair;
- QEC architecture search;
- resource-aware co-design;
- self-evolving AI-scientist orchestration.

The benchmark therefore tests the composition of these mechanisms, not name-level novelty.

## Hypotheses for missed knowledge

H-MISS-1: an AI-scientist or compiler paper may already expose a generic cross-layer capability contract under non-quantum vocabulary.

H-MISS-2: quantum QEC and quantum-algorithm discovery communities may independently implement the same slow/fast evaluation and memory semantics.

H-MISS-3: generic program synthesis/CEGIS may subsume proposed P10 language-growth behavior once exact proof obligations are exposed.

H-MISS-4: Bayesian metareasoning may subsume verification/query allocation once costs and partial evidence are formalized.

H-MISS-5: a donor-composed rule system may solve the exact arena completely; if so, the correct response is absorb and escalate, not tune a learner.

## Frozen implementation hypothesis

### H0 — donor-composed sufficiency

When all task-relevant state needed by the donor suite is visible, a donor-composed typed controller may equal ORION on the first heterogeneous exact arena. If H0 holds, record `MAX_R0_DONOR_SUPERSYSTEM_SUFFICIENT` and escalate the benchmark to hidden method/interface edits rather than claiming a learning win.

### H1 — general scoped-failure state value

A single domain-neutral failure contract

`FailureReceipt = (mechanic, representation, access_model, required_same, reopen_on_change, evidence_state, cost, outcome)`

will improve held-out research-action decisions across at least three of four domains versus:

- no failure memory;
- raw permanent negative memory;
- domain-local unscoped failure features;

under matched information/tool budget.

This is a P9/state claim, not a P10 novelty claim.

### H2 — donor-composed residual

After H1, there will exist protected cases where no available donor capability is admissible or sufficient under the declared state/budget, and the correct next action is one of:

`CHANGE_REPRESENTATION`, `CHANGE_INTERFACE`, `GROW_LANGUAGE`, `QUERY`, or `CANNOT_CHECK`.

Only these residual cases are eligible for a later P10 experiment.

## First executable arena design

Each episode contains opaque domain/task identities and a common typed state. The evaluator privately knows the correct next research action and outcome.

Candidate actions:
- `RUN_CURRENT_SPECIALIST`;
- `VERIFY_MORE`;
- `REOPEN_PREVIOUS_METHOD`;
- `SWITCH_SPECIALIST`;
- `CHANGE_REPRESENTATION`;
- `CHANGE_INTERFACE`;
- `GROW_LANGUAGE`;
- `CANNOT_CHECK`.

### Domain families

D1 synthesis: candidate program/gate method, staged verifier, grammar/library state.
D2 algorithm interface: representation/access route, cost/error/ancilla constraints, route admissibility.
D3 QEC: code/circuit/decoder/hardware state, fast proxy vs slow physical verifier.
D4 theorem reasoning: conjecture/proof state, formal library, proof obligations, counterexample/verifier state.

### Cross-domain holdout

Freeze at least one leave-one-domain-out evaluation. No domain label may be used by the generic scoped-failure policy. Domain-specific specialists remain available as tools but their identity cannot itself encode gold action.

## Baselines

B0 oracle specialist selector (diagnostic ceiling only).
B1 flat donor portfolio.
B2 donor-composed rule/meta-controller with all visible typed state.
B3 frontier generic research agent with same tool contracts/budget where runnable.
B4 no-history controller.
B5 raw permanent-negative-history controller.
B6 scoped typed ORION state, no P10.

P10 is forbidden in MAX-R0.

## Primary endpoints

Non-compensatory reporting:
- verified task/research-action success;
- false escalation;
- invalid specialist/tool call rate;
- verifier/tool cost;
- repeated-dead-end rate;
- correct reopen rate;
- abstention correctness;
- leave-one-domain-out transfer.

No one-number weighted reward may hide hard failures.

## Hostile tests

- remint all domain/task/tool identities;
- permute candidate/specialist order;
- same surface/history with opposite correct action;
- stale failure after representation change;
- terminology-only representation change that must not reopen;
- stronger oracle/interface hidden behind same label;
- verifier result unavailable until cost is paid;
- task where donor-composed rule system is exactly sufficient;
- task where no admissible action is knowable and `CANNOT_CHECK` is correct;
- task where a specialist succeeds despite previous failure because required context changed;
- future/protected outcome leakage mutation.

## Reopen triggers

Reopen research before implementation if:
- a donor already supplies the complete cross-domain state/control object;
- domain semantics cannot be represented without leaking the answer;
- the same rule trivially solves all cases from one visible coordinate;
- cross-domain holdout is not meaningful because domain-specific feature schemas cannot be aligned faithfully;
- the donor-composed baseline cannot be made strong/fair.

Reopen after outcome if:
- H1 fails on one domain family;
- B2 equals/exceeds B6 everywhere;
- an apparent gain depends on one domain identity;
- a broader representation/action vocabulary is exposed by failure;
- P10 residual cases are absent.

## Frozen interpretation

A positive MAX-R0 result may support only:

`GENERAL_TYPED_QUANTUM_RESEARCH_STATE_VALUE`

or a narrower domain-transfer statement justified by the results.

It cannot support autonomous quantum-method invention, new quantum algorithms, novelty, or real-domain superiority.

The programme continues upward regardless: if donors close MAX-R0, they become the incumbent and MAX-R1 targets the next residual.
