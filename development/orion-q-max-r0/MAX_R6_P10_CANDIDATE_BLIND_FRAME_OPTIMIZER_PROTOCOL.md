## Frozen search object

For every coefficient-local 12-term window on open H4 and equilibrium N2, enumerate every non-direct three-target subset `P=(P0,P1,P2)` and search TARE-3 auxiliary representations.

The search grammar is defined only by TARE/symplectic constraints.

### G1 — frame rank

Search both:

- rank-3 pairwise-anticommuting frames generated by three independent Pauli generators;
- rank-2 pairwise-anticommuting frames generated by a two-generator binary symplectic basis and the three distinct nonzero coefficient labels in `F2^2`.

For rank 2 the third frame vector is whatever the linear label map produces. No named construction is supplied.

### G2 — control labels

Enumerate every ordered triple of distinct two-bit labels admitted by the frame consistency constraints. Tag generators are solved from their required symplectic syndromes; no fixed Tag strings are supplied.

### G3 — target assignment / native matches

Enumerate all target permutations and all feasible native-match subsets. A native match is the generic TARE condition `R_k = P_perm(k)`, which makes the corresponding Restore word identity. Native-match cardinality is maximized lexicographically before support cost.

### G4 — Uanti central axis

Enumerate every central axis in the explicit `2m-1` TARE anticommuting-unitary sequence.

## Exact structural objective

For a candidate frame, labels, Tag generators, target assignment and central axis, compute

`C_support = C_Uanti_parity + 2 * sum_l w(S_l) + sum_k w(T_k)`

where

- `T_k = P_perm(k) * R_k` in binary symplectic representation;
- for m=3, `C_Uanti_parity = sum_k mult_k * (w(R_k)-1)` with multiplicity 2 on the central axis and 4 on the other two axes, matching the five-exponential TARE implementation's parity-network support accounting;
- Tag is applied/unapplied, hence the factor 2.

This objective is used only to generate candidate method structure. Equal fixed controlled-rotation / W / conjunction costs cancel between same-cardinality TARE-3 frames and are not a full block-encoding resource claim.

Optimization order:

1. maximize native-match count;
2. minimize `C_support`;
3. minimize Restore support;
4. minimize Tag support;
5. minimize frame support;
6. deterministic lexical witness ordering.
