## Development question

Can ORION construct an exact mixed quantum-failure benchmark in which superficially matched cases require different next actions, while preserving evaluator/model separation and making the marginal contribution of typed P9 structural coordinates independently testable against donor-complete routing/tool-selection baselines?

This packet does **not** freeze a P9/P10 positive hypothesis. It freezes only the M0 exact-world substrate needed to test one later.

## Expert-cell decomposition

The design is reviewed through five independent roles:

1. **Quantum information / algorithms:** validates state, gate, resource and representation semantics; blocks fake quantum distinctions.
2. **Formal methods / synthesis:** validates closure, reachability, unrealizability, receipts and specialist-verifier contracts.
3. **Automated discovery / meta-selection:** pressures every controller against routers, tool selectors, algorithm portfolios, QAS and scientific agents.
4. **ORION P9/P10 architecture:** maps only genuinely necessary fields into existing typed state/failure/mechanic abstractions and prevents a disconnected quantum ontology.
5. **Hostile novelty / reproducibility:** attacks metadata leakage, unmatched tool access, false escalation, post-outcome tuning and donor relabeling.

Any role can force a protocol reopen.

## Donor saturation assessment for this implementation atom

The current S0 rounds already strike the weak formulations needed to justify this benchmark:

- quantum gate/library growth and action-space expansion are prior work;
- parametric quantum program/algorithm synthesis is prior work;
- LLM/evolution/verifier quantum algorithm discovery is prior work;
- adaptive quantum solver-policy changes conditioned on diagnostics are prior work;
- generic synthesis unrealizability proofs and minimal-repair ideas are prior work;
- Lie-algebra controllability and minimal complete quantum generator pools are specialist prior work;
- per-task reasoning-paradigm routing and dynamic tool selection are prior work;
- automated quantum encoding/architecture selection is prior work;
- agentic abstention, evidence-grounded verification and provenance-authority audits are prior work.

Therefore QC-0A cannot claim novelty for routing, abstention, tool selection, exact obstruction proving, minimal repair, or structured scientific-agent workflows.

The bounded implementation question is only whether a **quantum mixed-failure benchmark** can faithfully isolate the marginal information needed for correct next-action arbitration and later test one ORION coordinate at a time.

Reopen if any of the following is true:

## Miss hypotheses

1. **Tool-presence leak:** obstruction cases alone expose an invariant checker while reachable cases expose a search tool.
2. **Dimension leak:** phase cases are one qubit and entanglement cases two qubits, allowing family recognition rather than reasoning.
3. **History leak:** failure-length or status code directly maps to the evaluator action.
4. **Receipt-label leak:** a field called `obstruction=true` trivially reveals gold.
5. **Authority laundering:** a partial specialist result is converted into a stronger action than it licenses.
6. **False impossibility:** finite search exhaustion is relabeled as language inadequacy.
7. **False sufficiency:** absence of an invariant obstruction is relabeled as guaranteed bounded reachability.
8. **Unmatched baseline:** ORION gets exact receipts or tool calls denied to the router/LLM baseline.
9. **Family memorization:** identity/surface tokens recur across train/test.
10. **Post-outcome ontology edits:** the typed field set is changed after seeing protected model results.
11. **Negative-control attrition:** hard no-edit/insufficient cases are removed because they lower headline accuracy.
12. **Specialist-as-ORION:** exact domain verifiers are mistakenly counted as P9/P10 contribution.

## Frozen M0 implementation hypothesis

> If mixed quantum cases are constructed with evaluator-only next-action gold, opaque/disjoint identities, matched surface/history/tool availability, and exact specialist evidence that is intentionally weaker than the final action label, then at least one weaker view can be made provably non-identifying while a declared full structural view is identifying, without granting P9/P10 any scientific authority.

A successful M0 establishes benchmark identifiability only. It does **not** establish that learning the full structural view is useful or that ORION outperforms a router.

## Frozen first-wave action vocabulary

M0 initially supports only the smallest action set justified by exact fixtures:

- `SEARCH_OR_OPTIMIZE_MORE` — current method language is not certified inadequate; a frozen exact fixture proves a route exists beyond the supplied failed prefix/budget.
- `EXPRESSIVITY_INVARIANT_OBSTRUCTION` — an exact invariant witness proves the declared method language cannot reach the target under the semantic contract.
- `INSUFFICIENT_EVIDENCE` — the visible receipts do not justify either continued search as sufficient or structural escalation.
- `NO_EDIT_KNOWN_METHOD_SUFFICIENT` — a known admissible method/route is explicitly available and independently verified; invention is unnecessary.

`BOUNDED_RESOURCE_BARRIER`, `CONTROLLABILITY_OR_LIE_CLOSURE_OBSTRUCTION`, and `REPRESENTATION_OR_INTERFACE_MISMATCH` remain protocol targets but are **deferred from first code** until exact verifier contracts are separately frozen.

## First-wave family design

### F1 — invariant obstruction

Reuse #640 exact families, but normalize presentation so dimensionality does not determine action. If one-qubit phase and two-qubit entanglement cases cannot be dimension-matched honestly in V0, action-level evaluation must stratify/hostile-test dimension shortcuts and a later generator must create matched dimensions before protected learning.

Specialist evidence may include raw invariant values or verifier receipts, but never an evaluator action label.

### F2 — reachable after failed prefix

Construct tiny finite gate-language tasks where:

- a supplied search prefix/history fails;
- exact exhaustive enumeration independently proves a solution exists within a larger frozen bound;
- the model receives matched failure language/status to an obstruction case;
- the correct next action is `SEARCH_OR_OPTIMIZE_MORE`.

The exact solution path remains evaluator-side during diagnosis.

### F3 — insufficient evidence

Construct paired cases where the supplied failure trace/receipt is intentionally truncated or a required verifier result is unavailable. The correct action is `INSUFFICIENT_EVIDENCE`, not invention.

A later tranche may expose an evidence-acquisition action; M0 only freezes the classification boundary.

### F4 — known-method sufficient

Expose a verified admissible existing method contract that solves the target under the same semantic/resource model. Correct action is `NO_EDIT_KNOWN_METHOD_SUFFICIENT` even if a more powerful candidate edit exists.

## Proposed M0 views

- `SURFACE`: opaque task/problem tokens + normalized presentation only.
- `HISTORY`: adds failed-step receipts but not method semantics/invariant/resource meaning.
- `METHOD`: adds frozen method/capability contract but omits decisive specialist evidence.
- `EVIDENCE`: adds specialist evidence receipts but not evaluator family/gold.
- `FULL_STRUCTURAL`: adds only the minimum typed linkage needed to interpret the receipt against target/method contract.

View names are evaluator configuration, not model-visible family labels.

The final lattice is not frozen until exact ceiling analysis proves which view collisions actually hold. If HISTORY or METHOD already identifies a family, redesign before learning rather than hiding the result.

## Specialist-verifier contract

Every specialist adapter must return a content-addressed evidence object with:

- verifier type/version identity (available equally to all baselines if tool use is allowed);
- semantic input digest;
- assumptions/preconditions;
- raw result/witness fields;
- validity status;
- what proposition the receipt licenses;
- explicit non-claims / what it does not establish;
- no evaluator next-action field;
- no task-family/gold field.

Corrupt, stale or assumption-mismatched receipts must fail closed.

## Frozen hostile tests

- identical SURFACE payload with different correct actions;
- identical HISTORY payload with different correct actions where mathematically possible;
- evaluator IDs/gold/family absent from every model view;
- train/dev/test identity tokens disjoint by construction;
- target/global-phase reminting leaves applicable quantum witness/action unchanged;
- tool registry and tool availability matched across paired cases;
- invalid/stale receipt cannot license escalation;
- finite failed search prefix plus hidden reachable route is not called expressivity obstruction;
- invariant-compatible does not imply bounded reachable;
- known verified method suppresses invention;
- missing decisive evidence produces `INSUFFICIENT_EVIDENCE`;
- row/order/surface reminting invariance;
- deterministic information ceiling computed for every view;
- any model result above its selected-view ceiling invalidates the run.
