# Development packet — issue #628 RSSI exact interaction benchmark

## Development question

Can ORION express and deterministically score the smallest exact benchmark that separates **task correctness** from **scientific-standing correctness** across framework changes, while forcing strong parent mechanisms to win their own cases and keeping protected authority/evaluator state outside the candidate policy?

This packet authorizes only the **research benchmark harness** needed to test that question. It does not authorize an ORION runtime mechanic, framework adoption, or a novelty claim.

## Atomic fibres

1. define a minimal public world representation containing framework/schema/operator/objective identities plus inherited claims, evidence, dependencies, obligations and negative records;
2. define protected gold separately from the public case;
3. define standing migrations over `PRESERVE / TRANSPORT / REOPEN / INVALIDATE / LEAVE_UNKNOWN`;
4. score task-answer correctness independently from standing-migration correctness;
5. fail closed when an affected inherited object is silently omitted;
6. fail closed when a candidate promotes/keeps authority where gold requires reopening/invalidation/unknown;
7. record protected-surface violations independently of task success;
8. generate at least three pilot families before broadening the benchmark: stale certificate after semantic change, operator invention reopening negative knowledge, and same answer/different scientific standing;
9. include no-change controls so a policy that always reopens or always evolves cannot pass;
10. use deterministic hidden-token reminting so IDs/surface names are not gold labels;
11. make the parent/control identity part of protected gold, not candidate input;
12. keep all V0 code under the research-extension tree; do not add a runtime import path or authority write path.

## Incumbent mechanics and negative history

ORION already has the stronger experimental pattern needed for this benchmark:

- P1 authority-value studies split `PUBLIC_CASES.jsonl` from `PROTECTED_GOLD.jsonl`;
- execution freezes bind source and holdout hashes before outcome access;
- matched arms are frozen by identity;
- protected/broad epistemic mutation is a catastrophic non-compensatory gate;
- zero-error Jump work already showed that an elegant new representation transition can have zero incremental value once the strongest parent is executed;
- P6 higher-order work already terminated `FORMAL_COMPONENTS_ONLY_NO_UNIFIED_CALCULUS`, so this benchmark must not be used as a pretext to invent a new calculus;
- donor rounds A-H for #627 have all materially narrowed the claim.

The benchmark therefore reuses the public/protected identity discipline rather than introducing another evaluation architecture.

## Parent-domain recovery

The programme has explicitly recovered, among others:

- M-open model discovery / experiment design;
- ontology/schema change impact and semantic validity;
- iterated belief revision and trace-sensitive revision;
- typed negative scientific knowledge;
- epistemic-state replication with immutable evidence log and semantic rollback;
- self-modifying Lean proof workflows under a fixed trusted checker;
- skill/verifier coevolution;
- objective evolution;
- evaluator-integrity and anti-reward-hacking controls;
- versioned scientific claim/evidence registries.

V0 must not claim novelty for any individual mechanism above. Its scientific question is whether their **interaction** creates a residual scientific-standing problem under recursive framework evolution.

## Saturation assessment

Novelty saturation is deliberately **not** closed: #627 remains `MATERIAL_PARENT_DISCOVERY_CONTINUES__RSSI_NARROWED_AGAIN` after eight material rounds.

Implementation saturation for this **benchmark atom** is nevertheless bounded enough to begin because:

1. the task contract is a falsifier, not an architecture commitment;
2. its first three families are direct executable consequences of already-identified interaction gaps;
3. the benchmark explicitly contains parent-owned controls and can terminate `DONOR_COMPOSITION_SUFFICIENT`;
4. no runtime or publication claim depends on a positive V0 result.

A new donor that already solves a pilot family is a reason to relabel/remove that family, not to rewrite the result.

## Challenge to saturation basis

The benchmark can be falsely positive if:

- the public surface leaks the required disposition through words such as `reopen` or `stale`;
- a policy can pass by always reopening every inherited claim;
- the candidate sees which parent owns the case;
- task correctness is used as a proxy for scientific validity;
- protected authority state is accidentally placed in public input;
- object IDs differ by family in a learnable way;
- hidden gold changes after policy outputs are observed;
- the benchmark only tests one-step migration and never exposes delayed F2 consequences;
- donor arms are made artificially weak or receive less information/edit power.

V0 hostile tests target the first seven immediately. Delayed F2 and donor-product execution remain later #628 fibres.

## Miss hypotheses

Relevant mechanics could still be missed because:

- database-migration / proof-assistant theorem-transport literature uses different vocabulary from epistemic standing;
- safety literature may frame the same problem as invariant preservation under self-modification;
- scientific workflow systems may encode authority as reviewer/checker custody without using the word authority;
- negative-memory systems may already implement context-version invalidation under a different term;
- multi-version concurrency / event-sourcing systems may supply a stronger exact lineage abstraction than the current benchmark representation.

These remain #627 reopen/search routes and do not block the V0 falsifier implementation.

## Reopen triggers

Reopen this implementation packet if:

- a pilot family is not deterministically identifiable from its protected gold;
- a trivial always-reopen / always-preserve / answer-only policy passes all hostile controls;
- candidate-visible fields encode family/gold labels;
- protected output or authority state leaks into public instances;
- the exact scorer cannot distinguish a correct answer reached through invalid standing migration;
- another live lane modifies the same research-extension files;
- donor saturation removes the interaction residual entirely.

## Frozen implementation hypothesis

A **stdlib-only, research-tree-local** module can generate deterministic public/protected cases for the first three RSSI families and score a policy output on independent dimensions:

```text
task_correct
migration_exact
all_affected_objects_accounted_for
invalid_promotion_count
protected_surface_violation_count
```

The pilot is non-vacuous only if:

1. a gold policy scores perfectly;
2. always-preserve, always-reopen and answer-only hostile policies each fail at least one required dimension;
3. same-answer/different-standing pairs receive different migration scores despite identical task-answer correctness;
4. candidate input contains no protected gold or parent-owner field;
5. deterministic regeneration with the same seed is byte-identical.

No ORION-RSE scientific positive is authorized by satisfying this implementation hypothesis.
