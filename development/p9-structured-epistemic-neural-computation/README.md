# P9 Structured Epistemic Neural Computation — benchmark bootstrap

## Development question

Before ORION trains any new neural architecture, can we define a **model-independent, exact structural benchmark substrate** that distinguishes the properties P9 actually wants to study from language, naming, topology and compute shortcuts?

The target scientific question is larger:

> Can learning over a dynamic typed epistemic state — claims, observations, representations, mechanics, evidence, failures, obstructions, dependencies and explicit unknowns — improve compositional/OOD problem-solving dynamics beyond matched text, anonymous latent and generic graph representations?

This first tranche deliberately does **not** answer that question. It builds the smallest exact-world object capable of falsifying bad versions of it.

## Research team / responsibility lenses

The research programme uses four interacting lenses rather than one architecture-first lane:

1. **Representation / topology:** graph, heterogeneous graph, hypergraph/cell complex, sheaf/local-chart, equivariant and object-centric representations.
2. **Algorithmic / operator learning:** neural algorithmic reasoning, action/operator learning, program/library induction, reusable modules and modular policies.
3. **Latent / temporal reasoning:** recurrent-depth, continuous latent reasoning, state-space/world-model and trajectory learning.
4. **Falsification / epistemology:** failure/negative history, `UNKNOWN`, obstruction, counterexamples, active inquiry, provenance, matched-information comparisons and authority separation.

A mechanism is promoted only after all four lenses agree on its exact role and nearest-work pressure.

## Atomic development fibres

### A. State representation

1. object identity distinct from surface label;
2. object type distinct from object identity;
3. relation semantics distinct from graph topology;
4. local representation/chart identity distinct from one universal embedding;
5. transport/mapping data distinct from adjacency;
6. history distinct from current state;
7. explicit unknown/unresolved state distinct from negative evidence;
8. provenance/source identity retained without becoming a predictive shortcut.

### B. Mechanic representation

9. mechanic identity distinct from human-readable name;
10. applicability/preconditions;
11. read/write footprint;
12. expected effect/post-state;
13. preservation obligations/invariants;
14. known failure boundary / negative history;
15. declared cost;
16. authority stays outside the learnable recommendation score.

P9 consumes P6/P6-successor mechanic semantics; it does not re-own them.

### C. Composition / local-to-global structure

17. pairwise relation compatibility;
18. multi-view cycle consistency;
19. compatible local views that can be integrated;
20. incompatible views that must remain an obstruction;
21. higher-order interactions not reducible to pairwise topology;
22. unseen composition of individually known mechanics.

### D. Learning / generalization

23. surface permutation invariance/equivariance;
24. donor/implementation invariance;
25. whole-domain transfer;
26. structural near-miss rejection;
27. failure-conditioned recovery;
28. calibrated `UNKNOWN`/non-identifiability;
29. matched-information text serialization;
30. matched graph/sheaf/NAR/latent compute accounting.

### E. Inquiry

31. distinguish uncertainty from a load-bearing defeater;
32. select evidence/computation that can change a downstream decision;
33. compare against uncertainty sampling, information gain, counterexample search and value-of-computation;
34. keep `CANNOT_CHECK` when no admissible discriminator exists.

## Incumbent ORION structures we consume

This tranche must not duplicate:

- P1 mutable K/W/M state and scoped reopening;
- P3 source-local projections, mappings, GLUE/obstruction and round-trip/cycle checks;
- P4 content-bound evidence and protected verification;
- P5 negative/failure history and cause-vs-recurrence separation;
- P6 `MethodRealizationView`, `StructuralSignature`, `MethodFibre` and composition contracts;
- P6-successor `HigherOrderEpistemicMechanic` typed read/write/precondition/requirement/preservation/cost semantics;
- P8 non-compensatory authority.

Current main already supplies claim-relative method fibres and a non-authorizing higher-order mechanic contract. P9 should learn **over projections of those structures**, not create parallel scientific authority objects.

### Heterogeneous / graph Transformers

**Absorb:** type-aware relations; local/global decomposition; structural encodings; scalable typed graph baselines.

## Bounded saturation assessment for this tranche

Enough structure is stable to build an **exact benchmark object**:

- identity must be separable from surface form;
- relation meaning must be separable from topology;
- local representation mappings can carry information not present in adjacency;
- current state and history can be distinct inputs;
- `UNKNOWN` and `OBSTRUCTION` must be distinct labels;
- mechanics can be represented as non-authorizing structural transitions;
- exact adversarial pairs can prove when a restricted input view is insufficient.

Not saturated and therefore excluded from the first implementation:

- final node/relation taxonomy;
- final sheaf/categorical mathematics;
- a universal latent geometry;
- a learned neural architecture;
- a universal definition of a mechanic;
- a universal active-learning objective;
- a final P9 paper claim.

## Challenge to the saturation basis

The apparent P9 structure may still collapse because:

1. a typed HGT/GraphGPS baseline may capture every useful distinction;
2. sheaf/local-chart structure may add no inductive value once relation features are matched;
3. NAR may already capture mechanic execution and OOD composition;
4. reusable-module learning may already capture mechanic discovery;
5. continuous latent recurrence may match explicit state after compute matching;
6. object-centric gains may disappear with enough data/compute;
7. an elaborate ontology may leak gold labels or encode the solver by hand;
8. scientific annotations may be too noisy for neural supervision;
9. active inquiry may reduce to ordinary information gain/value of computation;
10. a result may come from extra state/compute rather than epistemic structure.

The benchmark therefore begins with countermodels that make these failure modes measurable.

## Why prior searches could have been falsely flat

- `mechanic` appears as skill, option, program abstraction, operator, module, transition or policy;
- local representation compatibility appears under sheaf, alignment, multi-view consistency, schema matching or cycle consistency;
- explicit unknown appears as abstention, selective prediction, OOD, set-valued prediction or unresolved planning state;
- composition appears in NAR, program induction, neuro-symbolic reasoning, modular networks and category/topology literature;
- structural state appears in world models, object-centric learning, planning and graph learning rather than `knowledge representation`;
- failure-directed inquiry appears in CEGIS, model criticism, Bayesian experimental design and metareasoning.

These are mandatory reopen routes for #469.

## Competing implementation hypotheses

### H-I1 — exact hostile worlds are sufficient first substrate

A small model-independent benchmark can prove that surface-only and topology-only representations are insufficient on selected paired cases without presupposing the winning neural architecture.

### H-I2 — benchmark smuggles the answer into types

If the typed representation directly names the gold outcome (for example `GOOD_METHOD` or `CORRECT_MAPPING`), the benchmark is circular. Types must describe structural facts, not the target label.

### H-I3 — graph topology plus attributes is already sufficient

If every planned obstruction/mechanic case is trivially encoded by an ordinary typed graph, that is acceptable: P9 should then use the graph baseline and strike stronger architectural language.

### H-I4 — local transport is genuinely additional structure

If two cases share the same nodes/edges/types but differ only in mapping/transport data and require different correct outcomes, a dedicated local-transport/sheaf/lens representation remains worth testing.

### H-I5 — history is not necessary

If current state alone determines the correct mechanic in every exact world, failure history adds no information and must not be treated as a useful coordinate.

### H-I6 — explicit unknown is useful

There must exist cases where incomplete structure cannot justify either compatibility or obstruction, and the exact gold terminal is `UNKNOWN` rather than a forced binary decision.

## Frozen implementation hypothesis — tranche 0

Implement only a **model-independent `P9StructuralWorld.v0` benchmark substrate** with:

- typed atoms whose identity is distinct from surface label;
- typed relations whose semantics are distinct from adjacency;
- non-authorizing mechanic views with requirements/effects/failure boundaries;
- local affine transport maps for exact cycle/gluing countermodels;
- explicit failure-history records;
- explicit `UNKNOWN`, `GLUE`, `OBSTRUCTION` and mechanic-selection targets;
- deterministic surface-label permutation preserving gold structure;
- restricted-view signatures (`surface`, `topology`, `typed`) so tests can prove when a restricted view is non-identifying;
- exact validation that rejects dangling references, duplicate identities and malformed mappings.

Do **not** add PyTorch/JAX/model code in this tranche.

## RED / hostile tests before implementation

1. two worlds with identical surface + topology but different relation semantics have different gold mechanic choices;
2. two worlds with identical graph structure/types but different local transport maps have `GLUE` vs `OBSTRUCTION` gold;
3. missing transport data yields `UNKNOWN`, not obstruction;
4. same current state/mechanics with different admissible negative-history records changes the correct mechanic;
5. surface permutation changes labels but preserves typed/gold identity;
6. dangling relation target is rejected;
7. duplicate atom/mechanic ids are rejected;
8. unknown mechanic referenced by failure history is rejected;
9. a mechanic outcome cannot encode scientific/adoption authority;
10. topology-only fingerprint collision is deliberate on hostile pairs.

## Reopen triggers

Reopen this implementation hypothesis if:

- #469 finds a close donor whose benchmark already supplies all required exact hostile distinctions;
- the exact cases cannot be expressed without target-label leakage;
- P3/P6 ownership changes make the local mapping/mechanic projection invalid;
- an active overlapping branch introduces the same benchmark object;
- a hostile case shows the benchmark validator accepts contradictory identity or authority states;
- the first model comparison reveals an uncontrolled information or compute mismatch.

## Nonclaims

This tranche does not establish:

- a new neural architecture;
- superiority over Transformers/GNNs/sheaf networks/NAR/latent reasoning;
- a universal ontology of knowledge;
- method invention;
- general scientific reasoning;
- scientific authority;
- P9 novelty or peer-review readiness.

Its only intended terminal is a clean exact substrate from which those hypotheses can be tested without changing the target after model outcomes are seen.
