# P9 D1 — exact algorithmic method-transfer benchmark

## Development question

Can P9 move beyond the D0 synthetic state worlds without relying on noisy scientific prose by learning over **exact P1/P3 method realizations** across heterogeneous algorithmic domains?

The bounded target is not broad scientific-method understanding.  It is:

> Given source-grounded/authored exact method structures from several algorithmic/procedural domains, can a learner distinguish transferable structure, material obstruction, and genuine unresolved coordinates under surface/implementation/domain/combinatorial holdout?

## Upstream exact seeds

D1 consumes the already frozen P1/P3 structure pilot rather than inventing a new ontology:

- numerical methods: `bisection`, `threshold_calibration`, `nonmonotone_midpoint`;
- graph algorithms: `queue_bfs`, `layer_frontier_bfs`, `stack_dfs`;
- transactional workflows: `transaction_rollback`, `deployment_rollback`, `opaque_recovery`.

Upstream authority remains bounded exactly as recorded by `ORION.P1P3.StructurePilot.v1`; D1 does not retroactively turn those authored fixtures into an expert natural-paper corpus.

## Atomic fibres

1. Reconstruct the exact upstream method objects through P1 `MethodRealization`.
2. Define claim-relative D1 comparison coordinates without changing P1/P3 semantics.
3. Generate surface-reminted implementations while preserving exact structure.
4. Generate prospectively enumerated material corruptions on one load-bearing coordinate at a time.
5. Generate unresolved examples by withholding a load-bearing coordinate rather than fabricating a value.
6. Add double-corruption examples reserved for combinatorial holdout.
7. Separate domains, implementation identities and mutation families across train/dev/test.
8. Provide model views that distinguish transcript-only, untyped coordinate presence, typed structure, and same-information typed serialization.
9. Prevent domain/method/mutation identifiers from entering model-visible features.
10. Freeze domain-holdout and combinatorial-holdout manifests before learned results.
11. Preserve exact deterministic oracle labels from P3-style alignment logic.
12. Keep D1 completely disjoint from P10/P11 formal-math/frontier reserves.

## Frozen domains and primary holdouts

- `numerical_methods`
- `graph_algorithms`
- `transactional_workflows`

D1 V1 primary **whole-domain holdout**: train numerical + graph, test transactional workflows.

Secondary rotations may be executed as predeclared exploratory checks only after the primary result is sealed.

Primary **combinatorial holdout**: training contains single-coordinate obstructions; protected test additionally contains two-coordinate obstruction combinations whose individual coordinates appeared separately during training.

## D1 labels

- `ALIGNED`
- `OBSTRUCTION`
- `UNRESOLVED`

These are bounded P3-style structural comparison states, not method-equivalence/validity/adoption authority.

## Comparison coordinates

Use the current P1/P3 load-bearing structural vocabulary:

- preconditions;
- invariants;
- effects;
- progress;
- termination;
- reconstruction;
- failure semantics;
- dependency structure;
- lineage/provenance only as recoverability metadata, not a shortcut label.

## Model-visible views

`TRANSCRIPT`
- surface method/action labels and action counts only;
- reminted independently of gold.

`UNTYPED`
- coordinate presence/shape/dependency topology with semantic values removed.

`TYPED`
- explicit coordinate names and source-supported values; unknown remains explicit.

`TYPED_SERIALIZED`
- exactly the same typed information rendered as a canonical sequence/bag representation; used to separate information from architecture/encoding.

No view contains domain id, source method id, corruption name or gold.

## RED / hostile tests

- true analogue with disjoint surface vocabulary remains `ALIGNED`;
- same-looking method with precondition/invariant corruption is `OBSTRUCTION`;
- unknown reconstruction remains `UNRESOLVED` rather than obstruction or alignment;
- reminting every surface token leaves typed gold unchanged;
- domain id/mutation id cannot be reconstructed from model payload;
- duplicate/near-duplicate implementation ids do not cross splits;
- single-corruption train does not leak protected double-corruption test identity;
- transcript-only view cannot recover the deliberately reminted semantic coordinate;
- typed serialization and typed object view carry the same semantic information;
- oracle labels replay through existing P3 alignment logic.

## Stop/narrow rules

- if typed and same-information serialization perform identically, do not claim architecture value from the encoding alone;
- if transcript view solves after reminting, diagnose leakage;
- if a classical coordinate comparator reaches the ceiling, do not add a neural model merely for P9 branding;
- if whole-domain transfer fails because coordinate semantics are genuinely domain-specific, narrow rather than average domains;
- if D1 adds no result beyond the existing P3 deterministic pilot, retain it as reproduction/benchmark infrastructure and do not inflate P9.

## Nonclaims

D1 does not establish natural-paper extraction, expert agreement, formal-math reasoning, general scientific discovery, neural architecture superiority or downstream P10 utility.

Its terminal is a bounded exact algorithmic-transfer result or a documented null.
