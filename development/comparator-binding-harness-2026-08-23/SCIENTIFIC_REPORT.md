# P1--P5 comparator-binding harness: verified scientific report

**Date:** 2026-08-23  
**Authority:** live primary-paper/repository discovery, licence audit, interface analysis, and bounded entrypoint probes only. No protected outcome was accessed. No comparator-performance or superiority claim is authorized.

## Result

The lane audited 13 pinned repositories and four paper-only comparator families. It found one immediately executable, OSI-licensed external retrieval implementation for P2: **SIEVE / SkimSearchAgent**, paper-linked at `ielab/skim-search-agent`, Apache-2.0, commit `4a640296770c39b8274e7678c6de844daea9541c`. A credential-free fixture installed and completed with one scored instance, zero skips, and zero execution errors, emitting a full trace plus `rows.jsonl` and `results.json`. The fixture used a stub policy and scored zero; it proves only that the pinned entrypoint runs.

This does **not** close the comparator wave. The exact current terminal is:

> `CANNOT_CHECK_FULL_COMPARATOR_FREEZE`

The decisive problem is no longer “find some code.” It is **semantic and identity binding**: each frozen contrast needs an exact system ID, repo/commit/licence, adapter, information boundary, action and cost envelope, and output-terminal map. P3 and P4 currently freeze only comparator counts. P5 says six fixed comparators but its structural protocol names only three. P1 names nine families but leaves the strongest external slot unbound.

## Highest-value findings

### 1. P2 now has a credible runnable external candidate

SIEVE is the strongest verified candidate in this bounded lane because its primary paper directly links the repository, its Apache-2.0 licence permits adaptation, its current revision runs without a provider key on the shipped fixture, and it records the question, strategy, queries, actions, observations, surfaced documents, retrieved identifiers, answer, token/cost fields, and retrieval metrics.

It is not yet a P2 arm. Its native terminal is an answer/end/error/timeout trajectory, not P2's global acquisition-authority decision. A lawful adapter must therefore be frozen before outcomes and must not manufacture access to unavailable/censored routes, change the candidate-visible task world, or convert an empty answer into a favourable abstention. The next executable study is an outcome-blind SIEVE adapter over P2's identical provider/query/budget namespace, followed by archived-baseline task-world reproduction.

AutoResearchBench and SAGE are worlds/evaluators, not external agents at their public heads. AutoResearchBench has a runnable Apache-2.0 inference/evaluation pipeline but requires its released bundle and provider configuration. SAGE's paper-linked repository is data-only and has no licence or runner. AgentIR links model weights but no official orchestration repository.

### 2. P4's naturalistic comparator requirement is scientifically unresolved

None of the audited P4 neighbours provides the exact native terminal required by the successor: distinguish **unidentifiable, therefore `CANNOT_CHECK`** from **identifiable and correctly resolved** on same-source paired cases.

- ProvenanceGuard's paper consumes stable-ID MCP traces and emits per-claim verdicts plus answer-level `ALLOW/BLOCK`, but its author repository explicitly says code and data are not released.
- ProvenAI is Apache-2.0 and its entrypoint/import were verified. It emits trace graphs, cited answers, citation-audit verdicts (`faithful`, `mixed`, `over-cited`, `under-cited`) and resource-influence labels. Its prompt permits free-text “insufficient evidence,” but this is not a typed P4 `CANNOT_CHECK` terminal.
- AttributionBench is binary `attributable/not attributable`, with no third terminal and no repository licence.
- FIRE searches again when evidence is insufficient and ultimately emits binary `True/False`; its README's `run_fire.py` is absent and no repository licence is present.
- CLAIM-BENCH emits claim/evidence annotations, not an authority decision; it lacks a licence and unified runner.
- RewardHackingAgents is MIT-licensed evaluation-integrity infrastructure, but current editable installation fails from package discovery and its requirements omit PyYAML even though the runner imports it. That is a harness defect, not a negative scientific result.
- DeepSciVerify has no primary-bound code repository, so its escalation and unresolved semantics cannot be checked.

Therefore P4 must not relabel `BLOCK`, `not attributable`, parse failure, or free-text insufficiency as `CANNOT_CHECK`. The next research object is a **terminal-preserving adapter theorem and test**: an external system is admissible only if its observable output determines the three-way P4 decision on every candidate-visible fibre; otherwise its irreducible mixed-fibre error must be reported rather than repaired away.

### 3. P5's old MDA blocker changed, but did not disappear

The local P5 structural ledger says MDA is `ABSTRACT_ONLY` and blocked by `MDA_PRIMARY_FULL_TEXT_NOT_SOURCE_GROUNDED_2026-08-19`. That statement is now stale. Live arXiv **v3** (`2608.09696v3`, revised 2026-08-13) supplies full HTML, method text, detailed pseudocode, prompts, and appendices. It explicitly defines:

- a posterior over mechanistic hypotheses;
- predictive-check-triggered expansion in the M-open regime;
- LLM proposal of a novel unnamed mechanism;
- SMC structure/parameter inference;
- value-of-information experiment selection;
- hypothesis-space shrinking; and
- posterior forecasts on unseen interventions.

This is enough to reopen and repair the **source-grounding** record. It is not enough to bind a runnable official comparator. The only paper-linked repository, `murphyk/neuronbench` at MIT commit `c354622458c460b419cab821d482c879f0578377`, states that it is a **benchmark, not a solver**. Its reference pure-LLM baseline installed and its injectable-client interface executed locally, but no MDA implementation is present.

WorldEvolver remains paper-only: no author-bound repository was found. Self-Revising Discovery Systems does link an Apache-2.0 `lamm-mit/scienceclaw` implementation and the `categoryscienceclaw-mechanics` branch at `38b2f681e87272cd505c9b2671760fc3729756c2`. That substrate emits immutable typed artifacts, hashes, parent lineage, JSONL ledgers, open needs, and status mutations. It is a strong representation-regime parent, but it does not natively choose among P5's eight minimal revision classes or implement the protected preservation/fresh-transfer endpoint.

Thus P5 can replace the stale MDA blocker with the narrower and more accurate one:

> `MDA_V3_FULL_SOURCE_BOUND__OFFICIAL_SOLVER_CODE_NOT_RELEASED`

The six-versus-three comparator identity mismatch must also be repaired before a valid multiplicity freeze.

### 4. P1 has an open comparator candidate, but not a fair R7 arm

Agent Laboratory is MIT-licensed and supplies a documented end-to-end topic-to-literature-to-experiment-to-report workflow at commit `d9017d90e329112d2a80b7712f37ee9094d2cd27`. It is the cleanest OSI-open P1 candidate found here. AI Scientist-v2 is scientifically stronger and directly paper-linked, but its source licence is a Responsible-AI-derived custom licence rather than verified OSI open source; it also requires Linux/NVIDIA/provider infrastructure.

Neither is presently a fair P1 R7 comparator. Both consume a broad topic/configuration and emit research artifacts, whereas R7 requires byte-equivalent dossiers, the same registered actions/probes, matched model/retrieval/tool/time budgets, and a protected responsibility decision. A prompt wrapper is not enough: the adapter must expose whether the external agent's interface is constant on P1's required-decision fibres. If it is not, P1's own factorization theorem predicts irreducible error and the comparator should be classified as interface-limited rather than weak.
