# Development packet — issue #629 D4 delayed epistemic debt

## Development question

Can the successor-conditioned pair benchmark show a **causal later-generation scientific consequence** of losing a currently invisible lineage distinction, rather than stopping at a future-standing classification error?

The target is a research falsifier. It does not authorize a runtime controller or a new theoretical primitive.

## Atomic fibres

1. map each protected future-standing state to a family-specific valid successor action;
2. keep the current task answer identical within delayed pairs;
3. require the same D3 future transition within a pair;
4. let a D4 successor act from the migrated/predicted standing, not from protected gold;
5. count invalid successor commitments separately from missed opportunities;
6. show current-summary loss creates a delayed D4 error on at least one member of every pair;
7. show full-history and compact typed-lineage controls avoid all delayed D4 errors;
8. preserve family-specific actions so `REOPENED` does not collapse into one generic behavior;
9. make D4 scoring non-compensatory: a correct current task answer cannot offset an invalid successor action;
10. keep protected D4 action gold outside all candidate-visible state.

## Incumbent mechanics and negative history

The #629 exact pair core already establishes the information ceiling:

```text
CurrentSummary(a) == CurrentSummary(b)
FutureTransition(a) == FutureTransition(b)
GoldFutureStanding(a) != GoldFutureStanding(b)
```

Current-summary-only policies are therefore capped at 1/2 per pair, while full history and a compact registered typed-lineage state are expected to recover 100%.

This is standard state-sufficiency logic and not an ORION novelty claim. The new implementation atom asks whether the lost distinction has a **scientific action consequence in the next generation** under the protected standing/authority semantics.

## Parent-domain recovery

Direct parents include:

- predictive-state / bisimulation sufficiency;
- dynamic assurance and change-impact propagation;
- event-sourced replay;
- Epistemic State Replication semantic rollback;
- policy-version-bound authorization;
- negative-knowledge transfer and staleness;
- safe control under hidden/latent state.

Any parent with full history is expected to avoid the delayed error. ORION earns no credit merely for matching it.

## Saturation assessment

The D4 atom is bounded by the already-frozen three pair families:

- evidence-route dependency debt;
- negative-cause debt;
- authority-origin debt.

Each exposes a distinct later action:

- revalidate evidence vs commit;
- retry a formerly blocked method vs keep it blocked;
- reauthorize under external authority vs commit.

No additional family is needed to establish the causal non-vacuity of the benchmark.

## Challenge to saturation basis

A fake D4 effect could arise if:

- successor actions encode pair labels;
- a generic `REOPEN` action is scored as correct for every family;
- current-summary policies see hidden history;
- D4 uses a different future transition for the two variants;
- protected gold leaks through action names or IDs;
- full-history controls are denied lineage fields available to ORION;
- D4 score is aggregated with D2 answer accuracy so unsafe commitments are compensated away.

Hostile tests must cover these shortcuts.

## Miss hypotheses

A stronger prior may already study delayed safety/assurance debt under self-modification, or policy-continuity errors under version migration. If found, it becomes a parent/control and the ORION claim narrows again.

## Reopen triggers

Reopen if:

- D4 action correctness is not exactly determined by protected standing plus registered family semantics;
- current-summary-only policy exceeds its information ceiling through a surface leak;
- full-history or typed-lineage control makes any D4 error;
- a delayed error can be erased by compensating task score;
- family/action labels reveal protected pair membership;
- a stronger donor closes the complete delayed-debt interaction under matched information.

## Frozen implementation hypothesis

For DPAIR-1..3, a deterministic D4 runner can map each variant to one exact protected successor action. A current-summary-only successor must make exactly one D4 action error per pair, while full-history and compact typed-lineage successors make zero.

Required metrics:

```text
D2CurrentAnswerCorrect
D4SuccessorActionExact
D4InvalidCommitCount
D4MissedOpportunityCount
D4AuthorityViolationCount
```

Non-compensatory rule:

```text
D4InvalidCommitCount > 0 => recursive scientific integrity gate FAIL
```

regardless of D2 task accuracy.

A pass establishes only a causal delayed-debt benchmark. It does not establish ORION superiority over a matched full-history/donor-meta-product state.
