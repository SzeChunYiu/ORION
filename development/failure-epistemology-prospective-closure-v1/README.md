## 1. Pre-outcome scientific question

Does scoped negative history improve future scientific decisions relative to success-only/no-memory and naive failure-memory baselines **without causing negative transfer**, and if so does ORION need a new failure-learning primitive beyond the strongest mature composition already identified by the programme?

The strongest standard parent frozen before execution is:

```text
ATMS / scoped nogood environment
+ scientific responsibility / refutation gate
+ P7 complete/incomplete semantic transport
+ #477 defeater-directed / value-of-information inquiry
```

This parent receives the same public evidence, action/query menu, resource costs and transport witness as the ORION arm.

## 2. Candidate terminal frozen before benchmark implementation

Primary candidate terminal:

`FAILURE_MEMORY_USEFUL_BUT_STANDARD_METHODS_SUFFICIENT`

This terminal is earned only if all of the following hold on the frozen finite family:

1. scoped failure-aware behavior strictly reduces repeated dead ends versus `NO_FAILURE_HISTORY` on compatible recurrence cases;
2. scoped failure-aware behavior strictly reduces false exclusions versus `GLOBAL_FAILURE_BAN` on changed-context/repaired cases;
3. ORION never converts invalid execution/measurement evidence into scientific refutation;
4. ORION returns `UNRESOLVED` when transport or discrimination evidence is missing;
5. ORION uses a registered discriminating query when responsibility remains plural and a value-bearing admissible query exists;
6. the strong standard parent matches ORION on every protected case and on all non-compensatory gates;
7. the standard parent does not receive any information unavailable to ORION and vice versa;
8. neither arm grants refutation/adoption authority from the benchmark itself.

If ORION beats the strong parent on a protected case for a scientifically meaningful reason, the frozen negative/subsumption hypothesis is falsified and #508 remains open for a narrower positive residual. If both failure-aware arms fail to beat no-memory or create harmful negative transfer, use the corresponding negative terminal instead.

## 3. Frozen 32-case family

Eight families, four cases each. Case identities and gold decisions are frozen in the expected packet before the executable checker.

### E1 — compatible recurrence (4)

A prior validated scoped failure remains applicable under the same load-bearing context. The old failed option is again tempting/cheap.

Required behavior:

- `NO_FAILURE_HISTORY`: may repeat the dead end;
- `GLOBAL_FAILURE_BAN`: avoids it;
- exact-context / selective replay / parent / ORION: avoid it;
- protected correct action is the still-live alternative.

Scientific purpose: show **failure history contains useful information beyond current success-only state**.

### E2 — repaired measurement/evaluator (4)

The earlier negative came from a measurement/evaluator defect. The defect is now explicitly repaired with a verified semantic-change witness.

Required behavior:

- global permanent ban wrongly excludes the now-valid route;
- exact old negative must be reopened;
- parent/ORION permit revalidation/retry rather than silently carrying the old scientific exclusion.

Scientific purpose: negative knowledge is not permanent prohibition.

### E3 — semantic-preserving nonidentity (4)

Surface representation/version/name changes while a complete transport witness proves the load-bearing semantics unchanged.

Required behavior:

- raw full-context hash equality over-reopens;
- parent/ORION preserve the scoped negative through complete transport;
- string/name similarity alone is not the witness.

Scientific purpose: show why exact hashes are safe but not semantically complete.

### E4 — invalid execution/measurement cannot refute theory (4)

The observed failure is real, but responsibility evidence says the execution, instrument, or evaluator is invalid/non-identifying.

Required behavior:

- raw/global failure summary may ban the scientific claim incorrectly;
- parent/ORION emit no scientific exclusion and retain live scientific alternatives;
- if a local execution/config nogood is warranted, it remains local.

Scientific purpose: enforce the #452/#517 authority boundary.

### E5 — plural responsibility with one discriminating query (4)

Two responsibility hypotheses remain live. One cheap admissible query/test separates them and directly changes which action/exclusion is warranted.

Required behavior:

- no-history / global-ban / summary-only policies close or avoid prematurely;
- scoped-memory-only policy remains unresolved but does not choose the next information action;
- parent/ORION choose the registered discriminating query;
- the query is selected for decision relevance, not maximum irrelevant uncertainty.

Scientific purpose: failure can generate **a useful next question**, but #477 is the strong parent owner.

### E6 — no admissible discriminator (4)

Responsibility remains plural and all available tests have identical outcomes under the live hypotheses or are inadmissible.

Required behavior:

- parent/ORION return `UNRESOLVED` and do not spend compute for zero decision value;
- never-abstain policies fail open;
- global bans fail closed/broken-shut.

Scientific purpose: calibrated ignorance is part of failure knowledge.

### E7 — broken-shut negative transfer control (4)

The archive contains multiple real failures from **other** regimes/measurements/objectives. A current route is valid in the new registered context.

Required behavior:

- global/nearest negative retrieval can suppress the route merely because its method family appeared in failures;
- parent/ORION use scoped environment + transport and keep the valid route live;
- success-only/no-memory is allowed to succeed here, proving that failure history is not always beneficial unless scoped.

Scientific purpose: detect harmful overuse of negative memory.

### E8 — negative-results visibility / corpus-distortion (4)

The public archive manifest reveals a sampling/visibility asymmetry: registered studies exist but negative/null outcomes are systematically missing or unavailable from the candidate-visible corpus.

Required behavior:

- no-memory/success-only inference treats the visible successes as complete;
- parent/ORION mark corpus-level inference `UNRESOLVED` / `DISTORTION_SUSPECTED` and request or require missing-outcome evidence before global promotion;
- no one may fabricate the missing negative outcomes.

Scientific purpose: connect failure visibility to epistemic state without pretending the system knows hidden results.

## 4. Public/protected case contract

Each case has public fields only:

- current regime/context coordinates;
- candidate actions and costs;
- prior failure receipt or absence;
- responsibility state (`RESOLVED_SCIENTIFIC`, `RESOLVED_EXECUTION`, `PLURAL`, `NONIDENTIFYING`);
- scoped condition/nogood identity where already warranted;
- still-live alternatives and preserved-success identities;
- transport witness kind (`IDENTITY`, `COMPLETE`, `VERIFIED_SEMANTIC_CHANGE`, `INCOMPLETE_TARGET_AMBIGUOUS`);
- query/test menu and predicted outcome partition over live responsibility hypotheses;
- archive visibility manifest for E8;
- authority owner identity.

Protected evaluator fields:

- correct disposition/action/query;
- whether the prior negative scientifically applies;
- whether a retry is a repeated dead end;
- whether a proposed exclusion is false/globalized;
- whether a query has positive decision value;
- whether corpus-level closure is allowed.

No policy receives protected labels.

## 5. Frozen baseline ladder

1. `NO_FAILURE_HISTORY` — ignores negative history and chooses the cheapest currently available action; success-only-history analogue.
2. `GLOBAL_FAILURE_BAN` — any method family appearing in prior failure is permanently excluded.
3. `RAW_SUMMARY_NEAREST` — retrieves a prior failure by method-family/surface similarity and avoids the nearest failed option, without typed responsibility/transport.
4. `EXACT_CONTEXT_MEMORY` — applies a prior scoped negative only under full exact context equality; otherwise reopens.
5. `SELECTIVE_REPLAY_COMPATIBILITY` — uses registered compatibility coordinates and avoids obviously incompatible negatives, but has no semantic transport proof or defeater-directed query policy.
6. `STANDARD_PARENT` — independent reference implementation of ATMS/nogood scope + responsibility gate + P7 transport + #477 decision-relevant query selection.
7. `ORION_SCOPED_FAILURE` — uses `FailureKnowledge.v1` as the typed storage/interchange object, combines it with P7 transport and #477-style inquiry; does not add a new scientific primitive.
8. `ORACLE` — evaluator-only ceiling; excluded from superiority claims.

No parent may use more evidence, queries, or cost budget than ORION.
