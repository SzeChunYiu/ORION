## Problem

They have not been shown to improve scientific self-revision. T8 must implement the prospective discriminator requested by #455 without converting the still-provisional #452 taxonomy or unfrozen #454 structural-assimilation process into settled gold.

## Design decisions frozen before implementation

### D1 — benchmark-local revision vocabulary

The V3 benchmark uses **caller/freeze-declared string labels**. No new core enum is allowed. The initial development panel uses a deliberately narrower set sufficient to instantiate cause-confusable cases:

- `EVIDENCE_REPAIR`
- `MEASUREMENT_REPAIR`
- `WITHIN_CLASS_MODEL_REPAIR`
- `MODEL_CLASS_EXPANSION`
- `REPRESENTATION_REGIME_REPAIR`
- `EXECUTION_REPAIR`
- `EVALUATOR_REPAIR`
- `UNRESOLVED`

`OBJECTIVE_REVISION` and `METHOD_BASIS_REVISION` remain protected follow-up classes rather than development-panel gold because #288/#452/#454 have not frozen a shared responsibility taxonomy. The schema permits future protocol-local labels without changing framework code.

### D2 — same symptom, protected separating intervention

Each case freezes:

- public `symptom_family` and candidate-visible context;
- competing revision labels;
- allowed diagnostic actions and matched costs;
- protected action→outcome mapping;
- protected gold revision label;
- revision invasiveness rank used only for false-broad scoring;
- preservation obligations;
- allowed and protected surfaces;
- fresh-transfer family identity.

Candidate packets expose no protected outcome map or gold label. A commitment manifest binds those bytes.

### D3 — mechanism comparators, not false official reproductions

T8 implements deterministic **mechanism comparators** with explicit labels. It must not claim official reproduction of a donor system unless a frozen structural binding says so. Required comparator families:

- no-revision;
- direct broad self-edit;
- M-open-only model-class expansion;
- generic discriminator/causal diagnosis;
- full T7 responsibility-gated control;
- oracle ceiling (analysis only).

Controls:

- permuted feedback;
- no feedback;
- contradictory feedback;
- random diagnostic outcome;
- always broad revise;
- always unresolved.

### D4 — adaptivity is intervention-sensitive

The scorer separately reports the drop under feedback permutation/no-feedback. If the full policy is unchanged under evidence interventions, the implementation must not call the mechanism evidence-responsive.

### D5 — multiple endpoints, no scalar science score

Report separately:

- revision-label accuracy;
- false broad-revision rate;
- correct unresolved rate;
- preservation violation rate;
- containment/authority violation rate;
- diagnostic cost/actions;
- fresh-transfer success/harm when protected outcome evidence is supplied.

No weighted aggregate is a scientific endpoint.

### D6 — development panel is not confirmatory evidence

A small deterministic panel may be executed to prove instrumentation and control sensitivity. It is labelled `DEVELOPMENT_ONLY`. Its outcomes may not support P5 H1–H4, close #455, or promote a paper.

### D7 — confirmatory preflight is fail closed

Final execution requires exact non-placeholder bindings for:

- candidate subject revision;
- protected benchmark commitment;
- public packet hash;
- final split hash;
- independent evaluator hash;
- evaluation epoch;
- policy/baseline configuration hashes;
- protected fresh-transfer evaluator binding;
- structural baseline bindings for every load-bearing donor comparator;
- result-verification owner `#283` outside the candidate policy.

Because #454 has not frozen a programme-wide structural receipt, `BaselineStructuralBinding.v1` is **T8-local** and may record `MECHANISM_COMPARATOR_ONLY` / `CANNOT_CHECK`. Confirmatory READY requires every load-bearing comparator to be explicitly bound and no comparator to be falsely labelled official reproduction.

### D8 — policy never scores itself

Policy output contains only selected diagnostics/revision proposal and trace. A separate evaluator consumes protected gold. Policy code cannot return the scientific terminal.

### D9 — valid negative terminals are first-class

The final analysis schema supports:

- `REVISION_LEVEL_DISCRIMINATION_SUPPORTED`
- `M_OPEN_SUFFICIENT`
- `DIAGNOSIS_ONLY`
- `OVERCONSERVATIVE`
- `NO_INCREMENTAL_VALUE`
- `HARMFUL_REFUTED`
- `CANNOT_CHECK`

Implementation tests must not force the positive terminal.

## Competing implementation hypotheses

### H-A — one monolithic V3 benchmark runner
Rejected as primary design: easiest to build, but couples candidate policy, protected gold and scorer and makes leakage/self-scoring harder to detect.

### H-B — split candidate packet / protected suite / policy / independent scorer / confirmatory preflight
Selected. More files, but preserves the authority and access boundary already used by P5 freeze machinery.

### H-C — hard-code #452 eleven-class taxonomy in core framework
Rejected. #452 explicitly says the classes may be split/merged/rejected and has not reached a frozen terminal.

### H-D — postpone all T8 implementation until #452/#454 close
Rejected. We can implement generic schemas, protected custody, matched comparators, controls and a fail-closed final preflight now without asserting the final taxonomy or donor equivalence.
