## The terminal-preserving projection

Every adapter output must retain both:

1. the projected P5 class; and
2. the exact native terminal and payload digest.

An error, timeout, abort, empty patch, rollback or no-submission can project to `UNRESOLVED`, but its native terminal must not be erased or renamed. This prevents missing runs from becoming silent zeros or false scientific repairs.

### When a resolved singleton is lawful

A final action may map to one of the seven resolved classes only if all of the following were frozen before outcomes:

- a typed `revision_action.json` bound to the final native artifact hash;
- one host-validated input-native class certificate;
- a component-to-front registry and authorized write surface;
- the recomputed changed-component front set is exactly one class;
- the declared class agrees with that singleton front;
- the class belongs to the arm's prospectively frozen support set;
- before/after hashes prove every other front invariant;
- the scientific target identity is preserved where its class definition requires it;
- the candidate saw no protected label, diagnostic, gold patch, evaluator message, fresh-transfer target or harm information; and
- the action and native artifacts were sealed before an external evaluator opened protected outcomes.

The seven possible exclusive front fibres are:

| Exact front | Required semantic write surface |
|---|---|
| `EVIDENCE_REPAIR` | acquisition, routing, provenance, coverage or evidence authority only |
| `MEASUREMENT_REPAIR` | instrument, label, proxy, calibration, sampling or measurement mapping only |
| `WITHIN_CLASS_MODEL_REPAIR` | parameters, objectives, priors, inference or training inside the unchanged licensed model class |
| `MODEL_CLASS_EXPANSION` | hypothesis/model-family expansion or replacement only |
| `REPRESENTATION_REGIME_REPAIR` | state variables, ontology, encoding, interface, memory or typed-artifact regime only |
| `EXECUTION_REPAIR` | environment, dependency, toolchain, runtime, hardware, orchestration or implementation substrate only, with scientific method class fixed |
| `EVALUATOR_REPAIR` | a candidate-authored evaluator proposal or public-development evaluator only; never the protected evaluator |

Support is arm-specific: SWE-agent conditionally supports all seven resolved fronts. MOSS and DGM conditionally support only `WITHIN_CLASS_MODEL_REPAIR`, `MODEL_CLASS_EXPANSION`, `REPRESENTATION_REGIME_REPAIR` and `EXECUTION_REPAIR`; evidence, measurement and evaluator repair are unsupported and therefore project to `UNRESOLVED`.

Anything unknown, unsupported, multi-front, declaration-inconsistent or missing an invariance receipt maps to `UNRESOLVED`. A file extension, repository path name or the bare fact that source code changed is not a class proof.

The adapter classifies **what action was selected**. Whether it is the correct minimal revision, preserves the incumbent, transfers freshly and avoids harm is determined later by the external scorer.
