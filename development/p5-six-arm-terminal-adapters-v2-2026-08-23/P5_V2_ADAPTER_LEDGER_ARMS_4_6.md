## Terminal-preserving rule

The adapter record retains two separate fields:

1. `selected_revision_class`, one of the frozen eight P5 values; and
2. `native_terminal` plus its payload digest.

Projecting a failed, unsupported or ambiguous run to `selected_revision_class = UNRESOLVED` must never rename or discard the native terminal. Thus `OPEN_NEED`, `DRAWBACK`, `ABSTAIN`, compile failure, timeout, empty patch, draft-only and service failure remain visible even though their P5 projection is `UNRESOLVED`.

A resolved singleton is lawful only when every admissible world in the adapter-visible fibre has the same action class. Operationally, V2 requires:

- native `COMPLETE_SUCCESS` and a sealed final artifact;
- exactly one host-validated input-native class certificate;
- a complete action manifest bound to the native artifact;
- a host-recomputed changed-component front set equal to exactly `{c}`;
- agreement between certificate, declaration and write set;
- the class in the frozen arm support set;
- other-front invariance hashes and an authorized write surface;
- no protected information access; and
- sealing before independent protected evaluation.

The singleton describes the **proposed action front**, not whether that action is scientifically correct or minimal.

## C4 — ADIAS

ADIAS maintains persistent issue identity and lifecycle in `profile.json`, produces `round_diagnosis.json`, revision plans, patches, lineage, compile/runtime diagnostics, logs and development evaluation summaries. None of those raw states is a P5 class.

Its frozen V2 support set is:

- `WITHIN_CLASS_MODEL_REPAIR`
- `MODEL_CLASS_EXPANSION`
- `REPRESENTATION_REGIME_REPAIR`
- `EXECUTION_REPAIR`

`EVIDENCE_REPAIR`, `MEASUREMENT_REPAIR` and `EVALUATOR_REPAIR` are unsupported.

### Lawful conditional singleton

A selected `model_patch.diff` may map to one supported class only when it is accompanied by:

- a schema-valid `profile.revision_plan` and `revision_action.json`;
- one host-validated input-native certificate for the same class;
- the complete host-observed write set;
- an exact singleton front under the frozen registry; and
- hashes proving every other front invariant.

The proof does not use issue status, free-text `target_failure_mode`, compilation, rank or score. The refined fibre itself contains an independently certified class and a complete write set exactly on that front, so all admissible worlds in the fibre share the action type. Later protected scoring still determines whether the action was correct and minimal.

## C5 — Double Ratchet metric-only

The selected identity is `scripts/run_metric_evo.py`, not joint `run_co_evo.py`. Solver, task universe and skill bank must remain frozen while detector operations and the metric expression evolve.

### Metric diagnostics are not revision decisions

| Native metric observation | What it says | What it does **not** license |
|---|---|---|
| `CLEAN` | No configured detector reported a drawback for that observation | “No repair,” correctness, or any P5 class |
| `DRAWBACK` | One or more detectors report a drawback | `EVALUATOR_REPAIR`; the same symptom can arise from missing evidence or a defective metric |
| `ABSTAIN` / all abstain | The detector/battery declines to decide | Any substantive repair class |
| Detector class/evidence/severity/note/cost | Inspectable metric diagnostics | A minimal P5 responsibility front |
| `final_locked_agreement` or development agreement | A development scoring statistic | `EVALUATOR_REPAIR` or protected correctness |
| Marginal contribution, gap, elite rank or history | Metric-evolution selection diagnostics | A case-level revision decision |

The frozen synthetic fixture proves the decisive mixed fibre: the same native `DRAWBACK` can occur when the evidence packet omits decisive provenance (`EVIDENCE_REPAIR`) or when the evaluator scores valid evidence incorrectly (`EVALUATOR_REPAIR`). Therefore `DRAWBACK → EVALUATOR_REPAIR` is unsound.

### Only lawful conditional singleton

`EVALUATOR_REPAIR` is conditionally lawful only when a complete successful run yields all of:

- a separately frozen, host-validated **evaluator-defect certificate**;
- a sealed evaluator artifact;
- byte-identical solver, prompts, model/provider, tools, seed and task/split universe before and after;
- a complete action manifest whose write set touches only evaluator components;
- passed pre-frozen development validity gates; and
- no protected score in proposal, elite selection, rollback, synthesis, retry or replacement.

The certificate—not `DRAWBACK`, agreement or elite rank—identifies the action. Because the certified defect and complete mutation are both confined to the evaluator front, all admissible worlds in this refined fibre share `EVALUATOR_REPAIR` as the action type. Protected correctness/minimality remains externally scored.

| Native fibre | Lawful P5 projection |
|---|---|
| Final evaluator + evaluator-defect certificate + frozen-solver receipt + evaluator-only manifest + passed development gates | `EVALUATOR_REPAIR` |
| `DRAWBACK` alone | `UNRESOLVED`; mixed evidence/evaluator fibre |
| `CLEAN` alone | `UNRESOLVED` |
| `ABSTAIN` / all detectors abstain | `UNRESOLVED`, retaining abstention |
| Detector trace/category/evidence/severity/cost/note alone | `UNRESOLVED`; diagnostic only |
| Final expression, `result.json`, `metric.db` or evaluator artifact without defect certificate | `UNRESOLVED` |
| Agreement, rank, marginal statistic, gap or history | `UNRESOLVED`; protected versions are forbidden input |

For P5, official `eval_locked` must be a development-only surrogate. The independent custodian evaluates the final frozen metric exactly once on the protected panel and returns no outcome to the evolver.

## C6 — ScienceClaw

ScienceClaw is a source-grounded discovery substrate with immutable typed artifacts, UUID/content hashes, agent/skill/topic/parent lineage, JSONL ledgers, investigation drafts, open needs and status mutations. These provide provenance and representation mechanics, but not a minimal P5 action selector.

The prospectively frozen C6 support set is empty. Consequently **no resolved singleton is lawful in V2**, even if a wrapper attaches a plausible class declaration. Adding support would require a new outcome-blind successor protocol rather than post hoc relabelling.

| Native fibre | Lawful P5 projection |
|---|---|
| Valid immutable typed artifact with full lineage | `UNRESOLVED`, retaining artifact terminal/hash |
| `OPEN_NEED` with a valid artifact | `UNRESOLVED`, retaining native `OPEN_NEED`; never automatically evidence or measurement repair |
| Investigation result or draft | `UNRESOLVED`, retaining result/draft state |
| JSONL ledger, parent lineage or artifact status mutation | `UNRESOLVED` |
| Successful dry-run / no-post | `UNRESOLVED`, retaining `DRY_RUN`/`NO_POST` |
| Externally attached manifest/certificate claiming any resolved class | `UNRESOLVED`; all resolved classes are unsupported |
| Infinite posting or write-surface escape | Adapter-integrity failure → `UNRESOLVED` |
| Login failure, service timeout, tool failure or missing dependency | `UNRESOLVED`, retaining exact terminal |
| Invalid/empty artifact, missing result, draft-only or noncompletion | `UNRESOLVED`, retaining exact state |
| Mixed artifacts/needs/statuses suggesting several fronts | `UNRESOLVED` with mixed/ambiguous-front reason |

The frozen fixture makes the ambiguity concrete: `open_need_with_valid_typed_artifact` can arise from a missing primary source (`EVIDENCE_REPAIR`) or missing measurement resolution (`MEASUREMENT_REPAIR`). `OPEN_NEED` must remain the native terminal while the separate P5 projection is `UNRESOLVED`; it must not be renamed.

The adapter must run dry-only, disable Infinite posting, isolate candidate artifacts and freeze the topic, profile, tool/service identities, network, budgets and reset semantics. External APIs, models, tool datasets and generated-artifact rights remain unclosed.
