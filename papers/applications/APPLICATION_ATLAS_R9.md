# 1. Cross-paper certificate control plane

## 1.1 System object

The five-paper portfolio suggests a model-independent control plane for exact AI and algorithm workflows:

1. `NORMALIZE(problem, move_registry)` returns a bounded exact state and a normal-form certificate.
2. `IDENTIFY(state, representation, query)` returns either an exact answer, an exact interval/action set, a refinement request, or abstention with a fibre certificate.
3. `AUTHORIZE(action, evidence_graph, policy)` returns a typed proof of authority or a typed denial/nonpromotion witness.
4. `VERIFY(result, exact_checker)` returns a proof/replay receipt or a fail-closed terminal.

The composition is deliberately conjunctive. An answer can be mathematically correct but unauthorized; authorized but representation-underdetermined; well represented but produced from an unsound search cap; or fully derived but not independently replayed.

## 1.2 Reference decision semantics

For a proposed action `a` and query `q`:

- reject if the move registry is incomplete for a claimed production cap;
- normalize only under transformations whose semantic and objective premises are certified;
- compute the fibre diameter or action disagreement for the exact input visible to the predictor;
- when the fibre is unresolved, purchase a registered refinement, return the exact interval/action set, abstain, or route to the exact solver;
- evaluate typed authority after all record merges and refutations;
- execute only when the requested authority coordinate survives;
- verify the exact result and all certificates independently of the proposing model.

## 1.3 Cross-domain experiment

Issue #1411 owns the integrated study. The full control plane must be compared with native execution and all single-component ablations on at least two external task families.

Required measurements:

- exact-result correctness;
- invalid search-cap false acceptance;
- representation-collision decision error;
- unauthorized-action false acceptance;
- clean authorized acceptance;
- exact-solver and tool calls;
- certificate generation and verification cost;
- wall time, memory, and model/tool budget;
- attribution of every intervention to `NORMALIZE`, `IDENTIFY`, `AUTHORIZE`, or `VERIFY`.

The integration becomes a standalone application paper only if it yields a unique cross-domain effect not reducible to the component papers. Otherwise the evidence is imported into the individual manuscripts.

# 2. Q1 — production quantum/compiler realization

## 2.1 Mathematical input

Q1 owns the sharp support theorem for its frozen shared-Tag TARE compiler grammar. The application question is not whether the theorem is correct on that grammar; it is whether the support object corresponds faithfully to a production compiler/runtime resource after every admitted move is registered.

## 2.2 Exact bridge

Freeze one maintained quantum or Pauli compilation stack and identify:

- the exact intermediate representation;
- the production object corresponding to one support coordinate;
- the legal move set and pass ordering;
- the semantic equivalence relation;
- the resource objective, such as retained Pauli terms, auxiliary objects, exact-search variables, circuit objects, or verified compilation states;
- the map from Q1 normal forms to production artifacts.

A production witness must be serializable and replayable. A numerical reduction in an internal grammar is not enough.

## 2.3 Experiment

Arms:

1. native stack without theorem-guided normalization;
2. theorem-guided normal form only;
3. strongest native optimization passes;
4. theorem-guided normal form followed by native passes;
5. deliberately incomplete move registry, which must fail closed.

Metrics:

- exact semantic agreement;
- theorem support and actual production resource;
- compilation/search time;
- memory;
- final object/circuit/term count;
- certificate bytes and verification time;
- frequency of theorem inapplicability;
- cases where production moves improve beyond the abstract certificate.

Strong terminal: `APP_Q1_PRODUCTION_RESOURCE_MAPPING_MATERIAL`.

## 2.4 Manuscript payoff

A successful result supports a concrete statement that the sharp theorem controls a named production resource and materially changes a real compilation/search workflow. A null result still supplies a valuable boundary: the theorem is exact for the frozen grammar but the production stack has stronger global moves or a different resource owner.

## 2.5 Prohibited inference

Do not infer general quantum advantage, hardware performance, or universal compiler optimality from one stack or one grammar.

# 3. Integrated A+B — certificate-aware exact search

## 3.1 Mathematical input

The integrated paper separates:

- a finite-signature deletion ceiling;
- exact terminal complexity of a named proof language;
- production realization;
- cross-move interaction safety;
- search consequences of a verified support budget.

The interaction extension shows that local budgets need not add when cross-component moves exist. The application must therefore treat the move interaction graph or hypergraph as first-class data.

## 3.2 System object

A certificate-aware exact-search wrapper contains:

- a canonical state serializer;
- a complete named move registry;
- an abstraction map to finite signatures;
- a normalizer and certificate checker;
- an interaction graph/hypergraph builder;
- a cap solver for the declared interaction structure;
- an exact search engine restricted by the verified cap;
- a realizing terminal-state checker for any intrinsic lower claim.

## 3.3 Experiment

Issue #1407 owns the execution.

Required domains:

1. the registered XOR-aggregation grammar;
2. a production-faithful Pauli/modular compiler or exact optimizer;
3. one non-Pauli exact optimization domain with a finite move registry.

Arms:

- native/unbounded exact search;
- abstract zero-sum deletion cap;
- interaction-aware cap;
- strongest production reconstruction/cap;
- incomplete-registry hostile arm.

Metrics:

- exact optimum agreement;
- cap soundness;
- searched states/nodes;
- wall time and memory;
- cap tightness relative to realized terminal states;
- proof/certificate size;
- verification overhead;
- invalid-cap false acceptance;
- transfer across instance size and domain.

## 3.4 Decisive discriminator

The strongest result requires all of the following:

- a complete move registry;
- a production preimage for the critical abstract terminal state;
- irreducibility under every registered move;
- a nontrivial difference between abstract, interaction-aware, and production budgets;
- a material exact-search consequence under matched semantics.

Strong terminal: `APP_AB_CERTIFIED_CAP_MATERIAL_AND_TRANSFERRED`.

## 3.5 High-value uses

### Proof-carrying branch and bound

Attach the verified support cap and move-registry digest to the root problem. Every node restriction must preserve the cap premises or recompute the certificate. This can reduce the search universe while leaving the exact solver as the final authority.

### Certified preprocessing and symmetry reduction

Use the normal-form checker as a fail-closed preprocessor around SAT, CP, or exact enumeration. The application is strongest where advanced symmetry/dominance moves are present and need proof logging.

### Modular repair and compiler passes

Treat local repair rules as components and global reconstruction rules as cross moves. The interaction audit identifies when a sum-of-local-budgets claim is unsound.

## 3.6 Prohibited inference

A proof-language terminal number is not an intrinsic production lower bound without realization and complete-move irreducibility. Search-node reduction is architecture-specific and does not imply an algorithm-independent complexity lower bound.

# 4. Paper C — FiberGuard for learned combinatorial optimization

## 4.1 Mathematical input

For a representation `Phi` and exact target `T`, a fibre contains all instances with the same visible input. The target diameter in a fibre gives an architecture-independent error floor for every method receiving exactly `Phi`. Paper C also supplies exact intervals/action-set consequences and frozen feature-repair problems.

The application goal is to turn this into an online or pre-deployment gate for learned optimization.

## 4.2 Architecture-bound audit

A top-tier experiment must audit the representation actually available to the model. Acceptable examples include:

- message-passing or Weisfeiler–Leman equivalence classes for a graph-based learned optimizer;
- a frozen variable-constraint graph with declared node/edge attributes for MILP;
- a clause-variable graph representation for SAT/model counting;
- a declared handcrafted feature vector used by an algorithm selector or surrogate solver.

Floating embeddings are not treated as exact representation identity unless the architecture and numerical equivalence contract justify it. The preferred object is a symbolic architecture equivalence relation or canonical pre-network input.

## 4.3 FiberGuard policy

For each representation value, the gate may return:

- `ANSWER(value, radius=0, certificate)`;
- `INTERVAL([a,b], endpoint_witnesses)`;
- `ACTION_SET(A, disagreement_certificate)`;
- `REFINE(feature, acquisition_cost, child_certificates)`;
- `ABSTAIN(reason, unresolved_diameter)`;
- `ROUTE(exact_solver, budget)`.

A sequential policy uses the exact refinement recursion when the finite state is available. A minimum-cost static repair uses the registered bad-pair covering formulation.

## 4.4 Experiment

Issue #1404 owns the execution.

Arms:

1. learned model with no gate;
2. model-confidence rejection;
3. conformal/selective baseline;
4. exact fibre interval/action set;
5. static minimum-cost refinement;
6. sequential refinement;
7. route to exact solver.

Required domains:

- at least one architecture-bound graph/MILP/SAT lane;
- at least one non-isomorphic transfer lane;
- one finite exact panel with two target formulations;
- one public or production-derived corpus frozen before aggregate outcomes.

Metrics:

- selective risk and coverage;
- catastrophic value/action errors;
- high-confidence collision failures;
- interval/action-set width;
- exact-solver calls;
- feature acquisition cost;
- end-to-end time and objective/decision loss;
- worst-fibre, worst-domain, and size-stratified effects;
- train/test leakage across representation-equivalent instances.

Strong terminal: `APP_C_FIBERGUARD_REDUCES_DECISION_RISK_AT_MATCHED_COST`.

## 4.5 Exact application narratives

### Learned MILP guidance

Audit whether the frozen graph representation distinguishes feasibility, objective value, solution class, or branching action on the exact query being learned. When it does not, use a fibre certificate to route or refine before trusting the prediction.

### Graph-optimization surrogates

Generate or identify architecture-equivalent graphs with different exact chromatic number, independent-set value, or optimizer structure. Evaluate whether richer path/subgraph features close the registered collisions at acceptable cost.

### SAT and model counting

Audit clause-variable features for model count or solver-choice targets. Exact action disagreement is often more relevant than value error: two formulas may share the representation but require different branching or preprocessing decisions.

### Algorithm selection

Let `T(x)` be the winning solver or runtime vector. A fibre containing different winners proves that a single representation-only selector must make an error on at least one endpoint. FiberGuard can return a safe candidate set or route to a portfolio probe.

## 4.6 Top-tier scientific distinction

The application must be positioned against generic GNN expressivity, sufficient-representation theory, conformal prediction, and selective prediction. The residual contribution is query-specific exact fibres, content-bound collision witnesses, proof-carrying intervals/action sets, and exact cost-aware representation repair integrated into an optimization decision pipeline.

## 4.7 Prohibited inference

Finite panel closure is not all-size sufficiency. Exact worst-case collision error is not production prevalence. A richer feature that closes a panel may be too expensive or equivalent to nearly reconstructing the full instance.

# 5. Paper D — typed authority for agent and tool workflows

## 5.1 Mathematical input

Paper D assigns authority coordinates to seeds and rule caps, computes a least fixed point, retracts coordinates that lose every untainted proof, and tests graph merge by checking whether the union of component closures is already closed under all merged rules. Origin coordinates prevent two incompatible records from manufacturing a stronger permission.

## 5.2 Agentic system bridge

Represent:

- sources, memories, claims, tool outputs, approvals, and actions as claims;
- evidence type, consent, purpose, jurisdiction, review class, prospective status, or origin compatibility as authority coordinates;
- transformation/tool rules as positive conjunctive rules with caps;
- revocation or direct refutation as explicit removals;
- approved cross-record composition as bridge rules.

The system authorizes an action only when the exact required coordinate reaches it through a finite seed-founded proof tree.

## 5.3 Benchmark

- cap confusion and nonpromotion;
- two-record hybrid proof;

- authorized bridge;
- a case that requires negation, defaults, probability, or inconsistency and must therefore be rejected by the positive model.

Arms:

1. untyped reachability;
2. ingestion-time ACL;
3. lineage/provenance eligibility filter;
4. typed caps;
5. typed caps plus origin-sensitive merge safety.

Metrics:

- unauthorized-action false acceptance;
- clean-authorized acceptance;

- certificate bytes;
- policy-encoding disagreement.

Strong terminal: `APP_D_TYPED_AUTHORITY_PREVENTS_REVIEWED_OPERATIONAL_ERROR`.

## 5.4 High-value uses

### Multi-agent shared memory

Prevent a shared summary from hiding that its supporting records are private, revoked, untrusted, or incompatible with the requested action. The distinctive test is merge-induced authority, not merely lineage display.

### Tool authorization

Attach a required license/origin coordinate to a high-impact tool action. A model may recommend the action, but execution requires a typed proof that the authority survives the full evidence path.

### Scientific evidence retraction

After a source or computation is withdrawn, replay the typed graph to identify which claims remain usable under theorem-grade, bounded-computation, prospective, or other evidence classes. This tracks declared authority, not truth.

### Data-use and jurisdictional control

Use coordinates for consent, purpose, data class, or jurisdiction. This application requires domain-owned policy review and cannot be self-certified as legal compliance.

## 5.5 Top-tier scientific distinction

Current provenance and agent-governance work already covers lineage, action certificates, memory filtering, causality, minimal supports, and deletion robustness. The residual application must isolate exact cap-preserving nonpromotion, fixed-point merge safety, and origin-sensitive anti-splicing, then demonstrate a reviewed error that lineage-only or untyped systems miss.

## 5.6 Prohibited inference

The positive calculus does not decide truth, law, probability, inconsistency, defaults, or arbitrary negation. A same-author synthetic policy cannot establish real policy usefulness.

# 6. Nonquantum paper — proof-producing disjoint binary-kernel packing

## 6.1 Exact algebraic bridge

Let `H` be the `3 x n` matrix whose columns are a sequence in `F_5^3`. A nonempty zero-sum subsequence is exactly a nonzero selector

`x in {0,1}^n` with `H x = 0 (mod 5)`.

Packing `k` pairwise-disjoint zero-sum subsequences is exactly packing `k` nonzero binary kernel vectors with pairwise-disjoint supports.

This translation is exact. It does not turn the result into a generic linear-code theorem: coefficients are restricted to binary selection and the group/rank are frozen where the constants are used.

## 6.2 Algorithm benchmark

Issue #1408 owns the execution.

Engines:

1. subset-sum/factorization dynamic programming;
2. independently generated SAT or CP-SAT;
3. symmetry-aware canonical search;
4. AI-proposed invariant/cut lane with separate cut soundness checking.

Instance classes:

- exact `C_5^3` threshold controls;
- planted disjoint-kernel instances;
- adversarial near-threshold negatives;
- random rank-three column multisets;
- at least one transfer parameter where no ORION constant is assumed.

Metrics:

- exact status agreement;
- solved instances and closed strata;
- wall time and memory;
- proof/certificate bytes;
- independent replay time;
- valid/invalid proposed-cut counts;
- resource-bound and disagreement terminals.

Strong terminal: `APP_NQ_SEARCH_TO_PROOF_TRANSFER_REPRODUCED`.

## 6.3 High-value uses

### Search-to-proof conversion

An AI system may propose a normalization, invariant, branching rule, or cut. The harness accepts it only after an ordinary proof or a complete checker validates soundness. Failed conjectures remain recorded as negative curriculum.

### Exact solver benchmarking

The threshold instances combine symmetry, packing, modular arithmetic, and proof obligations. They form a demanding benchmark for SAT/CP-SAT, dynamic programming, canonical generation, and proof logging.

### Modular balanced batching

In domains where items carry exact `F_5^3` residue vectors, disjoint zero-sum subsets are independently balanced batches. The early constants provide exact worst-case thresholds for two and three batches on the frozen group. A real batching claim requires a domain whose resources are genuinely modular and whose batch constraints match the theorem.

## 6.4 Prohibited inference

Algorithmic benchmark success does not prove the mathematical constants, novelty, or `D_4(C_5^3)`. A modular batching interpretation is not a real-world optimization result until the domain mapping is independently justified.
