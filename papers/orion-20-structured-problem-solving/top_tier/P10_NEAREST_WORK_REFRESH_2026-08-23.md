# ORION-20 nearest-work refresh — 2026-08-23

**Programme:** #977 · **Scope:** immediate pre-submission saturation for the OCME maximum claim · **Method:** three changed-vocabulary search rounds (FunSearch-successor vocabulary; skill-library-invention vocabulary; library-learning/abstraction-growth vocabulary) over the 2025–26 lane.

## Maximum claim under test

> Obstruction-Certified Method Expansion (OCME): a system may expand its method language only after independently establishing that the protected target lies outside the reachable closure of the frozen registered method basis under a declared information/access/resource model. A minimal semantics-preserving outside-closure edit must then create new verified held-out reach that cannot be recovered by stronger search, repair, synthesis, library learning or evolutionary method search at matched resources.

## Saturation outcome

The 2025–26 lane is dominated by **verified evolutionary/RL program search** (AlphaEvolve, AlphaProof, DeepSeek-Prover-V2) and **skill/library growth** (AutoSkill, Voyager lineage, DreamCoder lineage). Every strong system verifies *candidate correctness*; **none certifies non-reachability of the target from a frozen registered basis, and none treats obstruction as a licensing condition for language expansion**. The OCME object survives contact with the strongest donors. What the refresh *does* change: any native headline must give AlphaEvolve-class and DeepSeek-Prover-class donors literal first refusal at matched resources — they are now concretely runnable, not hypothetical.

## Upward moves per absorbed donor (no claim narrowing)

- **D1 AlphaEvolve → higher-level problem (b) + protected experiment (c):** AlphaEvolve discovers programs in a general-purpose language with verified evaluators; it has no registered-basis semantics and cannot certify that a discovery was *unreachable from the frozen basis*. Concretely: (i) run AlphaEvolve-class evolutionary search **restricted to the registered old language** on both frozen generated settings — the exact-closure proof predicts zero reach (this is first refusal executed, not asserted); (ii) run it unrestricted at matched resources on the same originating targets and measure whether it recovers the same primitive — if it does at lower total resource, OCME's matched-resource clause fails there and the boundary gets reported; if it does not, the expansion admissibility claim is strengthened against the strongest donor in existence.
- **D2/D3 AlphaProof + DeepSeek-Prover-V2 → protected experiment (c):** the native verifier-backed study: DSV2 (open weights) at minimum, AlphaProof-class if accessible, receives the originating obstruction task suite in Lean with the method basis frozen; endpoints per the existing gate (verified solve improvement, obstruction-diagnosis accuracy, false expansion rate, full resource vector).
- **D6 AutoSkill → higher-level problem (b):** the missing licensing condition for skill-library growth. Their system answers "what skill to add"; OCME answers "when is adding it *licensed*". Adapt, don't avoid.
- **D8 DreamCoder → stronger theorem (a):** relate compression-based library growth to closure: characterize when wake-phase abstraction is guaranteed to remain inside `Cl(B)` (alias/macro), so that obstruction certification is exactly the condition under which growth escapes it. This gives DreamCoder's practical success a formal boundary and OCME its necessity argument.
