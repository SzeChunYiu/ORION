# ORION-20 non-rescue successor question — outside-closure discovery

Identity: `ORION20.OUTSIDE_CLOSURE_DISCOVERY.v1`.

The previous primitive-minimality attempt established that AND and OR can both be minimal singleton bases under the frozen template; it therefore cannot support a unique indispensable primitive. Reordering primitives or testing another basis is forbidden rescue.

The new scientific object is different:

> Given a prospectively frozen donor grammar `G`, initial information `x`, and resource budget `B`, can a method produce an externally verified object that is not in the donor closure `Cl_G(x,B)` under the same information and budget?

A result counts as an outside-closure discovery only if an objective native verifier accepts it and an exhaustive/complete closure checker certifies non-membership in `Cl_G(x,B)`. Merely using a different search order, renaming a primitive, or exceeding the donor budget does not count.

This question is not answered by the old minimal-basis result: that result compares generating bases inside one already-fixed closure, whereas this identity asks whether verified objects exist outside the frozen donor closure at all.
