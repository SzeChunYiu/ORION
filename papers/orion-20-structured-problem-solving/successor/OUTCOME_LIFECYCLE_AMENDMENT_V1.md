# ORION-20 outcome-lifecycle amendment V1

Date: 2026-08-22
Status: semantic clarification / no novelty or authority claim
Applies to: ORION-20 successor OCME / structured problem-solving contract

## Why this amendment exists

ORION-20 distinguishes lower-level causes, method-language obstruction, candidate edits, donor comparison, outside-closure verification, transfer, and independent reproduction. The harness implementation exposed an important semantic boundary that should be explicit in the paper contract:

- a missing O0--O6 proof object is **unresolved**;
- a verified donor subsumption, obstruction, impossibility boundary, or failed frozen transfer is a **negative research result**;
- neither may be rounded up to a method-language success.

## First-right-of-refusal remains mandatory

Before a method-language jump can be considered, the registered lower-level O1 families must be explicitly accounted for. The current bounded harness registry requires evidence for:

1. more search/compute;
2. representation/interface repair;
3. implementation/environment repair;
4. premise/library retrieval;
5. action-abstraction / macro mining;
6. theorem-prover / proof repair;
7. program synthesis;
8. evolutionary method/program search.

If one of these route families is missing, the state is `CANNOT_CHECK` with an active resolution obligation. The statement `all_registered_baselines_exhausted=true` is not a substitute for the evidence ledger.

A successful lower-level route is a causal result and closes method-language escalation for that episode.

## ORION-20 unresolved states

Examples of ORION-20 `CANNOT_CHECK` include:

- a required O1 route has not been executed;
- obstruction verification is missing or self-certified;
- outside-closure status is unverified;
- held-out transfer or false-expansion evidence is missing;
- independent reproduction is still open;
- a protected verifier/evaluator is unavailable.

Each such state should carry `ResearchResolutionObligation.v1` with the missing object and admissible next action. The harness should try to resolve it when the protocol permits.

## ORION-20 negative states

Examples of genuine negative results include:

- **donor subsumption**: a strong donor obtains the same reach under the frozen model;
- **verified obstruction / impossibility boundary**: the current closure cannot reach the target under the frozen semantics;
- **failed frozen transfer**: an outside-closure edit does not survive the held-out transfer/false-expansion contract;
- **falsified candidate**: semantic preservation or another required property is demonstrably false.

These should be represented as `ResearchNegativeResult.v1`, not `CANNOT_CHECK`.

Negative assimilation may register donor subsumption, close a candidate branch, register an obstruction, reopen a dependency, trigger reframe/search, or revise a paper/framework claim. It may not self-authorize invention, novelty, adoption, or publication.

## Outcome separation invariant

ORION-20 therefore requires:

\[
\mathsf{missing\ proof\ object}\Rightarrow\mathsf{UNRESOLVED},
\]

\[
\mathsf{verified\ refutation/obstruction/subsumption}\Rightarrow\mathsf{NEGATIVE},
\]

\[
\mathsf{O0\text{--}O6\ satisfied}\Rightarrow\mathsf{METHOD\ EXPANSION\ SUPPORTED},
\]

with no coercion between these classes.
