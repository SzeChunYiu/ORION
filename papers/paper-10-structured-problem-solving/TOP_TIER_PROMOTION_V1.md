# P10 top-tier promotion V1 — Obstruction-Certified Method Expansion

**Programme:** #977  
**Existing state:** successor maximum-claim manuscript is prospective; historical negative/donor-closed evidence remains immutable.  
**Top-tier state:** `SCIENTIFIC_OBJECT_NOT_YET_EARNED`

## Maximum claim to earn

> **Obstruction-Certified Method Expansion (OCME):** a system may expand its method language only after independently establishing that the protected target lies outside the reachable closure of the frozen registered method basis under a declared information/access/resource model. A minimal semantics-preserving outside-closure edit must then create new verified held-out reach that cannot be recovered by stronger search, repair, synthesis, library learning or evolutionary method search at matched resources.

This is above "agents invent methods", proof repair, tactic learning, program synthesis and evolutionary code/method search. All receive first right of refusal.

## Stage 0 — exact language/closure object

Before experiments, define for each domain:

- atomic method basis `B`;
- legal composition/closure operator `Cl(B)`;
- representation/interface/access model;
- tool/library/oracle set;
- verifier semantics;
- resource envelope;
- equivalence relation distinguishing new semantics from aliases/macros/compressions.

If closure membership is not independently checkable for the claimed edit, method-language expansion authority is `CANNOT_CHECK`.

## Stage 1 — donor-complete verified solving

Run under matched semantic information and total resource vector:

- native state + strong search;
- retrieval/premise selection;
- proof repair/failure-triggered intervention;
- tactic/macro/library mining;
- program synthesis;
- evolutionary code/method search;
- P9 representation repair without method expansion;
- search-more / compute-more controls;
- ORION structured workspace with method language frozen.

A P10 result requires verified correctness, not tactic prediction or evaluator score alone.

## Stage 2 — obstruction certification

A valid obstruction may be:

- exact finite non-reachability;
- machine-checked lower bound;
- exhaustive bounded non-reachability;
- independently verified resource-bounded obstruction under a predeclared search class.

Invalid certificates include timeout, low model probability, one failed proof, missing tactic prediction, or a search run that did not cover the registered class.

The certificate must rule out, under the same model:

1. missing information/access;
2. representation/interface repair;
3. implementation/environment defects;
4. missing premise/library retrieval;
5. stronger registered search;
6. proof/program repair;
7. synthesis;
8. evolutionary method/program search.

## Stage 3 — outside-closure edit

Candidate edits may introduce a new semantic operator, composition law, primitive/grammar element, verification/selection primitive, or representation-regime edit only when it changes reachable method semantics and carries an explicit correspondence.

A name, macro or abbreviation expanding entirely into `Cl(B)` is `KNOWN_COMPOSITION`, not invention.

## Stage 4 — protected transfer

Freeze held-out obstruction families before edit generation. A promoted edit must:

- close or materially move the certified obstruction;
- preserve verifier/semantic target or provide a checked correspondence;
- introduce no hidden tool/access/oracle widening;
- transfer beyond originating instances;
- survive donor-complete search/synthesis/evolutionary comparators;
- have low false-expansion rate on known-method controls;
- reproduce in an independent implementation.

## Required evidence scale

Top-tier broad OCME authority requires at least:

- **two independently verified outside-closure expansions** from distinct obstruction families; and
- **two verifier-backed domains** or one domain plus a second qualitatively distinct formal/executable setting;
- at least one expansion found/generated without hand-coding the final edit from the gold obstruction solution.

A single Lean macro/trick is insufficient.

## Primary endpoints

- verified solve/reach improvement;
- obstruction-diagnosis accuracy;
- false obstruction rate;
- false language-expansion rate;
- outside-closure verification;
- held-out transfer;
- semantic-preservation failures;
- verifier calls/search depth/time-to-first-correct;
- total resource vector;
- independent reproduction rate.

## Strongest hostile attacks

- more search closes the target;
- representation repair closes the target;
- library/premise retrieval closes the target;
- synthesis/evolutionary baseline finds the same edit;
- generated method is only a macro in old closure;
- obstruction checker is incomplete but reported as complete;
- verifier feedback leaks the needed edit;
- held-out family was visible during edit design;
- new operator changes target semantics rather than method reach;
- ORION uses more total resources;
- method generator certifies its own novelty.
