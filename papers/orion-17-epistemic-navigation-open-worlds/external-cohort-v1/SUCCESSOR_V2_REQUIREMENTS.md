# ORION-17 rule-disagreement successor V2 — minimum validity requirements

This is **design guidance only**, written after V1 terminated `NO_DISCRIMINATION`. It does
not authorize reuse of V1 outcomes as protected evidence and does not register a new rule.

A future successor identity must satisfy all of the following before protected outcomes.

1. **Outcome definition frozen in the protocol.** Bind the exact measurement script,
   commit/version, CLI arguments, history depth, `n_changes`, package-root handling,
   `false_closure_retention` definition, and ERROR/TIMEOUT/CANNOT_CHECK semantics.
2. **Prospective nondegeneracy tests.** Controls must prove that the donor-coarse policy can
   both preserve and reopen on each supported repository layout. A layout for which the
   policy mechanically collapses to always-reopen is excluded or normalized before outcome
   scoring, using a rule that does not inspect protected SOUND/UNSOUND outcomes.
3. **Untouched corpus.** Exclude every repository in the historical 8-project campaign and
   all 20 V1 disagreement repositories from fresh-confirmation N.
4. **No threshold rescue.** The historical density threshold 1.5 and rivals 49/216 may be
   retested as frozen hypotheses. Any layout/graph/new-threshold hypothesis derived after V1
   is a separately named theory with separately derived and protected data.
5. **Identifiability gate before rule comparison.** After measurement, if the usable
   nondegenerate cohort contains fewer than two outcome classes, terminal must be
   `CANNOT_CHECK_MECHANISM__OUTCOME_CONSTANT`. Rule accuracies are descriptive only.
6. **Symmetric rule treatment.** Identical inclusion, measurement, missing-data handling,
   and inferential gates for density, module count, edge count, and any prospectively added
   rival.
7. **Strong controls.** Include a nondegenerate known-sound control, known-unsound control,
   layout-equivalence control, and a detector mutation that must fail.
8. **No post-outcome corpus repair under the same identity.** If nondegeneracy or outcome
   variation fails, close the identity and design a genuinely new question.

A scientifically useful V2 should distinguish mechanisms because the protected outcome
varies on informative cases, not because one stratum or one repository layout mechanically
receives a particular label.
