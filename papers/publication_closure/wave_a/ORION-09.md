# ORION-09 Publication Closure Wave A V1

## Maximum current claim

ORION-09 distinguishes four objects that must not be collapsed: intrinsic support, proof-derived support ceiling, objective-indexed certificate validity, and representation/feature identifiability. Current evidence is exact but concentrated in a limited set of compiler families. The Wave-A question is whether the geometry transfers to a genuinely different public family or can be derived from a stronger cross-family theorem.

## Top-tier discriminator: choose exactly one before outcomes

### Route A — independent public family

- [ ] Select one independently maintained compiler/problem family whose representation, objective, and native certificates differ materially from the current families.
- [ ] Record inclusion criteria before selecting instances; no family may be chosen because preliminary outcomes fit the geometry.
- [ ] Bind public repository/version, benchmark corpus, native cost/resource outputs, compiler configuration, and licence/access terms.
- [ ] Translate the four ORION-09 objects without changing their meanings. If an object is not identifiable in the new family, register `NOT_IDENTIFIABLE` rather than inventing a proxy.
- [ ] Freeze predictions and falsifiers before running the family.

### Route B — stronger general theorem

- [ ] State a cross-family theorem with explicit assumptions from which at least two existing family results follow as corollaries.
- [ ] Include a countermodel showing why each assumption is necessary or disclose an open sharpness boundary.
- [ ] Mechanize/check the theorem independently where feasible.
