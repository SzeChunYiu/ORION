# FiberGuard R19 replacement — exact joint learned/fallback route profiles

Date: 2026-08-27

Status: analytic repair of the paired-route layer after the earlier R19 diagonal-pair shortcut was falsified. Generic selective routing, finite minimax duality, convex hulls, Pareto pruning, and reject-option learning are donor-owned. The FiberGuard-specific object is the complete statewise **joint** learned/fallback route profile under one statewise oracle, explicit acquisition timing, and a source-bound legal-pair relation.

## 1. The rejected shortcut

A learned action family and a fallback family do not automatically induce only the same-label pairs `(A,A),(B,B),(C,C)`. Nor may six original actions be replaced by three coordinatewise paired actions merely because labels match. The transformation is valid only if it preserves the actually attainable statewise loss-profile set at the authority level being claimed.

The hostile three-state matrix retained by this package has six original profiles

- `(0,70,0)`, `(70,0,70)`, `(70,70,70)`;
- `(70,70,70)`, `(70,70,70)`, `(70,70,70)`.

The exact randomized minimax value is `35`, witnessed by a half/half mixture of the first two profiles. A diagonal coordinatewise pair-maximum shortcut yields only `(70,70,70)` and value `70`. Thus the shortcut is neither zero-cost nor information preserving. It is revoked for theorem, experiment, manuscript, and application authority.

## 2. Exact paired-route subject

Let `X` be a finite hidden-state fibre. Fix:

- learned terminal actions `a in A`, with oracle-relative losses `L_a(x)`;
- fallback actions `b in B`, with oracle-relative losses `F_b(x)`;
- one route observation `psi:X->O` available when the learned/fallback decision is made;
- a source-bound legal compatibility relation `C subseteq A x B`;
- learned-representation acquisition charge `c(x)>=0` in the same unit and against the same statewise oracle;
- a route map `g:O->{learned,fallback}`.

If an absolute fallback or deferral cost is registered, it enters `F_b(x)` only after subtracting the same statewise oracle `C*(x)`. Equal units without a common baseline are not sufficient.

### Post-acquisition routing

The learned representation has already been acquired before routing, so its charge is sunk on both arms:

`p_post[a,b,g](x) = c(x) + L_a(x)` if `g(psi(x))=learned`,

`p_post[a,b,g](x) = c(x) + F_b(x)` if `g(psi(x))=fallback`.

### Pre-acquisition routing

Fallback may be selected before the learned representation is acquired:

`p_pre[a,b,g](x) = c(x) + L_a(x)` if `g(psi(x))=learned`,

`p_pre[a,b,g](x) = F_b(x)` if `g(psi(x))=fallback`.

Any fallback-specific acquisition cost is included directly in `F_b`. The two policy languages are different experimental arms; a post-acquisition rejection cannot claim a refund.

Let `P_post` and `P_pre` be the finite sets of all profiles generated by every legal `(a,b)` and every route map on the attained observation cells.

## 3. Exact deterministic and randomized values

### Theorem C-R19.1 — exact legal-profile enumeration

For timing `t in {pre,post}`, the deterministic robust paired-route value is

`V_det^t = min_{p in P_t} max_{x in X} p(x)`.

Under the frozen worst-state expected-loss semantics, the randomized value is

`V_rand^t = min_{lambda in Delta(P_t)} max_x sum_p lambda_p p(x)`.

#### Proof

A deterministic paired route policy is exactly a legal learned/fallback pair plus one route decision for each attained observation cell. Substitution into the corresponding timing formula produces one profile in `P_t`, and every enumerated profile specifies such a policy. Root randomization over complete deterministic paired policies produces exactly the convex hull of `P_t`. Taking the worst state and then minimizing gives the two formulas. ∎

Randomization remains an expected-loss guarantee. Worst-state, worst-random-seed safety is the deterministic value and is not improved by mixing.

### Corollary C-R19.2 — actual-pair certificate

A finite randomized upper receipt must name the actual learned action, fallback action, route-cell map, acquisition timing, and complete statewise profile for every deterministic policy in its support. A label-only pair receipt is insufficient.

By the finite minimax/basic-solution argument from R13, an exact upper certificate needs at most `|X|` actual deterministic paired policies. A matching exact adversarial state prior is the lower certificate.

## 4. The joint profile is not determined by its marginals

### Theorem C-R19.3 — marginal nonidentifiability

The separate sets `{L_a}` and `{F_b}` do not determine the paired-route policy language or its value. The legal compatibility relation and route observation are independent required inputs.

#### Proof by exact counterexample

Take two states, learned marginals `(0,100),(100,0)`, and identical fallback marginals. Let the route observation distinguish the states.

- If every learned/fallback combination is legal, the cross pair consisting of the first learned action and second fallback action routes to zero loss in both states, so the exact joint value is `0`.
- If only same-index pairs are legal, the attainable nondominated profiles are `(0,100)` and `(100,0)`, whose exact randomized minimax value is `50`, with adversarial prior `(1/2,1/2)`.

The learned and fallback marginal bytes are identical in the two systems. Only the joint compatibility relation differs. ∎

### Consequence

If the implementation permits learned and fallback actions to be selected independently, the registered subject must include the full Cartesian product `A x B`. If only a subset is legal, that subset requires a source-bound admissibility argument. Diagonal pairing is never inferred from shared names.

This example also shows that separate pointwise marginal safety is not joint route safety: each state has a zero-loss learned action and a zero-loss fallback action, yet the diagonal-only joint system has no zero-safe policy.

## 5. Exact compression criterion

For a finite profile set `P subseteq R^X`, define its randomized lower image

`K(P) = conv(P) + R_+^X`.

It records every expected statewise profile attainable by mixing, together with all componentwise worse profiles.

### Theorem C-R19.4 — lower-image equivalence

For finite profile sets `P` and `Q`, the following are equivalent:

1. `K(P)=K(Q)`;
2. for every nonnegative state prior `mu`,
   `min_{p in P} mu.p = min_{q in Q} mu.q`;
3. every profile in `P` is componentwise dominated by a convex combination of `Q`, and every profile in `Q` is componentwise dominated by a convex combination of `P`.

#### Proof

`1 -> 2` follows because a nonnegative linear functional has the same lower support value on equal upward-closed convex sets. `3 -> 1` follows because each generating profile lies in the other upward-closed convex set, and convexity plus upward closure then gives both inclusions. For `2 -> 1`, if the two closed polyhedral upward sets differed, strong separation would provide a separating normal. Upward closure forces every component of that normal to be nonnegative; normalization gives a state prior whose lower support values differ, contradicting 2. ∎

### Publication rule

A proposed paired-policy compression is reusable for randomized minimax and every adversarial-prior lower certificate only after this lower-image equality is proved or machine-checked. Matching one scalar minimax value is weaker and may be accidental. For deterministic monotone-risk reuse, the stronger deterministic Pareto receipt from R13 remains required.

The exact checker in this package implements condition 3 with rational arithmetic.

## 6. Route observation is part of the policy language

### Theorem C-R19.5 — coarsening monotonicity

If route observation `psi_coarse` is a coarsening of `psi_fine`, then every coarse route map is realizable under the fine observation. Therefore both deterministic and randomized paired-route values under the fine observation are no larger.

However, the ranking of two learned/fallback pairs may reverse under coarsening.

#### Hostile ranking reversal

For two states, pair A has learned profile `(0,100)` and fallback profile `(100,0)`. Pair B is constant `(30,30)` on both arms.

- Fine route observation: pair A routes statewise and has value `0`, beating pair B's `30`.
- One coarse cell: pair A must choose one arm for both states and has value `100`, losing to pair B's `30`.

Thus the route-observation serialization and every coarsening are content-bearing certificate inputs. A certificate proved under a finer observation cannot be applied to a coarser deployed route interface.

## 7. Acquisition timing is not cosmetic

### Theorem C-R19.6 — exact no-refund identity

For a fixed legal pair and route map,

`p_post(x)-p_pre(x) = c(x) 1{g(psi(x))=fallback}`.

Hence `p_pre <= p_post` componentwise and pre-acquisition routing can never be worse when the fallback avoids learned acquisition. Equality holds exactly when no positive-cost state is sent to fallback.

Relative to the always-learned policy:

- post-acquisition route difference on a fallback state is `F_b(x)-L_a(x)` because cost is sunk on both arms;
- pre-acquisition route difference is `F_b(x)-[c(x)+L_a(x)]` because fallback also saves learned acquisition.

These are different fallback-alignment estimands.

#### Hostile timing reversal

On one state, let learned terminal loss be `0`, fallback loss `5`, and learned acquisition cost `10`.

- Pre-acquisition: learned total `10`, fallback total `5`; route to fallback.
- Post-acquisition: learned total `10`, fallback total `15`; route to learned.

A single route label therefore cannot cover both timing semantics.

## 8. Paired upper certificates after R17

R17's pointwise statement remains valid: if simultaneously valid upper bounds `U_L` and `U_F` are attached to one actual legal pair, selecting the arm with the smaller bound certifies the selected loss by `min(U_L,U_F)`.

R19 adds the missing attainability obligations:

1. the learned and fallback actions must form a legal pair;
2. their statewise profiles must be jointly bound under one oracle;
3. the route rule must be a function only of the deployed route observation/certificate bytes;
4. the acquisition timing must match the loss profile;
5. any action-pair or policy compression must preserve the exact lower image at the claimed randomized authority level.

Separate marginal validity does not discharge these joint obligations.

## 10. Replacement application gate

Before any paired learned/fallback ASlib or production experiment is authorized, freeze:

1. solver/scenario/corpus revisions and one common statewise oracle;
2. learned and fallback action families and the exact legal compatibility relation;
3. route-observation bytes and every coarsening;
4. pre-acquisition and post-acquisition arms as separate policies;
5. statewise learned, fallback, feature, timeout and censoring losses;
6. exact joint profiles and lower-image receipts;
7. calibration/training splits without held-out retuning;
8. matched-information learned-only, fallback-only, R16 marginal rejection, paired deterministic route, paired randomized route, frozen 16-NN, and a standard learned algorithm-selection comparator;
9. hostile cases where fallback is worse, separate marginals pass but the joint route fails, and coarsening changes the selected pair;
10. positive, null, adverse, timeout, resource and disagreement terminals.

A positive result requires the paired route to improve the frozen deployment objective after all acquisition and fallback costs, not merely to calibrate one marginal action. A null or another sign reversal remains publishable evidence.
