# Negative-Recovery Scientific Closure Contract V1

**Status:** `FROZEN_BEFORE_R4_HISTORICAL_CURRICULUM_OUTCOME`  
**Parent:** #964

This file defines what would count as completion of the bounded V1 research programme. It does not contain R4 outcome values.

## Required evidence coordinates

### E1 — exact generated recursive recovery
Must bind an immutable result showing:
- learned atomic recovery;
- learned unseen-composite recursive recovery;
- native-controller recovery;
- single-shot and random baselines;
- exact-mechanic no-overescalation control;
- deterministic replay.

Required terminal:
`ORION_NEGATIVE_RECOVERY_EXACT_GENERATED_WORLDS_SUPPORTED`.

### E2 — historical failure curriculum
Must bind the frozen R4 30-record leave-one-out result:
- learner receives only pre-`Failure class` text;
- titles/directory/class/repair sections withheld;
- all 30 episodes held out once;
- learned and native lanes;
- shuffled-label controls;
- per-class recall and leakage scan.

Required terminal for the strongest V1 claim:
`ORION_HISTORICAL_FAILURE_CURRICULUM_REPAIR_RESPONSIBILITY_SUPPORTED`.

If R4 is negative, **V1 may not claim historical failure learning**. The R4 errors become the next negative-recovery object and the programme remains open unless a successor reaches a supported historical-curriculum terminal or a rigorous non-identifiability/lower-bound is established.

### E3 — prospective owner-domain recovery
Must bind a failure state whose working recovery was unknown when the first successor was frozen, and preserve every intermediate negative.

For QG-20 V1–V5 the closure record must serialize:
- original certified non-identifiability/error floor;
- every successor representation;
- complete-domain and held-out-size outcomes;
- selection-before-label evidence where applicable;
- independent verifier decisions;
- deterministic replay;
- donor ownership.

The strongest currently admissible owner-domain terminal is:
`QG20_RECOVERY_V5_SIGNED_COMPLETE_WEIGHT_SURVIVES_N5_COLLISION_CHALLENGE`.

### E4 — lower-bound / do-not-escalate control
The closure must retain at least one case where the correct research move is **not** a more complex learned method. Current qualifying controls include:
- EA1 exact-mechanic sufficiency;
- finite-menu exhaustive-search dominance;
- donor-known theorem/prior-art collapse.

A system that always invents or escalates cannot satisfy V1.

### E5 — failure-preserving instrumentation
Instrument failures discovered during the programme must remain explicit, including:
- verifier REJECT initially hidden by a wrapper using exception-on-nonzero;
- incorrect mixed-cell reporting primitive;
- fixes that alter observability/reporting must be distinguished from changes to scientific protocol/feature/domain/threshold.

No instrument defect may be silently recoded as a scientific negative or vice versa.

## Strongest V1 terminal

The programme may close as:

`ORION_NEGATIVE_TO_WORKING_METHOD_RECOVERY_SUPPORTED`

**only if all five evidence coordinates above are satisfied**, including a supported R4 historical-curriculum terminal and the prospective QG-20 working-method terminal.

Meaning of this terminal is bounded:

> On the frozen ORION failure corpus and exact generated recovery worlds, historical failure descriptions contain reusable signal for broad repair responsibility; atomic failure knowledge composes recursively; and in one prospectively frozen owner-domain case, recursive negative analysis changed the state representation through preserved failed successors until a donor-grounded working method closed the exact recovery domain and survived a larger label-blind collision challenge.

It does **not** mean:
- universal autonomous scientific discovery;
- arbitrary natural-language failure recovery;
- new quantum algorithm invention;
- all-n sufficiency of the recovered representation;
- novelty of signed/complete quantum weight enumerators;
- authority for the recovery system to self-adopt or self-certify research results.

## Honest alternative terminals

If E3 succeeds but E2 remains negative:
`ORION_PROSPECTIVE_NEGATIVE_TO_WORKING_METHOD_RECOVERY_SUPPORTED__HISTORICAL_CURRICULUM_OPEN`.

If E2 succeeds but E3 fails/saturates:
`ORION_HISTORICAL_FAILURE_CURRICULUM_SUPPORTED__PROSPECTIVE_WORKING_METHOD_NOT_EARNED`.

If a genuine impossibility closes E3:
`ORION_NEGATIVE_RECOVERY_LOWER_BOUND_CLOSED_ON_PROSPECTIVE_OWNER_DOMAIN`.

A PR merge, green CI, or manuscript readiness never substitutes for these scientific terminals.
