# Publication programme scoreboard

Machine-readable tracker for GitHub issue #97. It records whether each of
ORION-P1..P5 is `PEER_REVIEW_READY`, `BLOCKED`, or `CANNOT_CHECK` from
**repository artifacts**, not from closed child issues or local falsifiers.

Authoritative inputs, in order:

1. `papers/orion-1N-*/JOURNAL_READINESS.md` terminal line
2. `protocol/PROTOCOL_V1.json` freeze status and UNBOUND execution bindings
3. claim ledgers (`CLAIM_LEDGER*.md` / `CLAIM_LEDGER_V1.json`)
4. optional `PEER_REVIEW_READY*.md` attestation files

`publication_status.json` is generated by `scoreboard.py`. CI rejects a
committed snapshot that does not match the derived tree, and it rejects a
`PEER_REVIEW_READY` label when `JOURNAL_READINESS.md` still says
`CANNOT_CHECK`.

```text
python3 research/publication/scoreboard.py          # print derived JSON
python3 research/publication/scoreboard.py --write  # rewrite the snapshot
python3 research/publication/scoreboard.py --check  # fail if snapshot drifted
```

Issue #97 must stay open until every paper is `PEER_REVIEW_READY` on `main`.
A closed child issue is not that terminal.
