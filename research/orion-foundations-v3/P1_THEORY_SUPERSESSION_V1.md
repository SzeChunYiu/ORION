# P1 theory supersession and execution-boundary record V1

## Decision

The theoretical identity of P1 is owned by the ORION foundations programme, not by the RR1 finalizer implementation or any one protected execution lane.

The following theory is authoritative for future P1 manuscript upgrades:

```text
P1 object = minimal responsibility-conditioned epistemic mutation
P1 main theorem = minimal repair in a formulation poset/closure system
P1 impossibility = failure transcript alone cannot identify colliding causes
P1 recursion law = accepted repairs decrease a well-founded unresolved rank
P1 adoption boundary = diagnosis/proposal has no self-issued adoption authority
```

Any P1 prose implying that one RR1 tuple, one Slurm finalizer, or one protected execution protocol defines the general reconstruction theory is superseded by this record.

## RR1 role

RR1 is an empirical/protocol instantiation that may test a bounded prediction of P1. It can contribute:

- occurrence-bound execution evidence;
- one protected intervention outcome;
- a bounded failure/repair observation;
- evidence about implementation feasibility.

It cannot by itself establish:

- unique responsibility identification;
- universal minimal repair;
- naturalistic transfer;
- recursive convergence;
- protected adoption safety;
- programme-level novelty.

## Implementation policy

P1 execution code may be replaced or redesigned when it fails the frozen theory-to-experiment contract, but outcome-bearing records and historical negatives remain immutable. A faster or cleaner execution lane does not receive permission to weaken the target theorem or move its gate after outcomes.

## Current execution-agent instruction

Execution agents must implement the frozen P1 experiment derived from the theory. They must not revise the theory to fit Slurm, custody, token, model, or benchmark constraints. Infrastructure failure yields a typed execution terminal, not a theory change.
