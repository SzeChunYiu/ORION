# Adoption recommendations after local falsification

## Shared ORION framework — **ADD as experimental infrastructure**

Recommend landing `orion.transfer` as a non-authoritative internal problem-solving layer:

1. `ProblemSignature` retrieves structurally similar distant problems.
2. `AlgorithmCell` records assumptions/invariants/stopping/failures/falsifiers.
3. `StructuralTransferSolver` verifies transfer before selection.
4. Optional distinct-domain cross-confirmation reduces accidental analogy risk.

Do **not** advertise far-domain retrieval itself as novel. Its value is in making analogical search operational and fail closed inside ORION.

## P1 — **strong V2 candidate; do not mutate current V1**

Add a future `ResponsibilityDiagnosability` stage before responsibility attribution:

- test whether available observations can distinguish responsibility classes;
- actively select a low-cost/low-risk discriminating probe when they cannot;
- withhold reframe authority when responsibility is not identifiable;
- make formulation/search-universe mutation a responsibility-scoped capability.

Why it survived locally: a blind probe returns exactly zero information gain and no license; a discriminating probe makes a formulation fault identifiable, while an evidence diagnosis remains unable to license formulation rewrite.

Why not modify current P1 V1 now: the active P1 lane has already begun pilot work and exposed instrument degeneracy. This mechanism should be evaluated as a clean V2 or future-method extension rather than silently changing the registered study.

## P2 — **performance candidate / exploratory comparator; novelty only as composition**

Add a future conservative allocator above the existing route machinery:

- BM25/simple retrieval is the safe fallback;
- exploration spends explicit safety credit;
- unavailable providers are censored and leave open obligations;
- route allocation never certifies task closure;
- baseline-preserving constraint is tested on the lower-bound ledger.

The local toy world demonstrates a strict gain while maintaining the declared floor, but bandit exploration itself is old. Do not disturb the active #126 execution lane; evaluate this later as an exploratory comparator or V2 mechanism.

## P3 — **strong V2 candidate**

Add typed scientific lens checks to mapping evaluation:

- every admitted transformation should support source -> mapped/global -> source recoverability on protected semantic coordinates;
- multi-source cycles should be tested for consistency;
- failing cycle/round-trip tests should become `OBSTRUCTION`/plural views rather than a forced global merge;
- transportability/measurement conditions stay explicit assumptions.

This likely strengthens P3's false-merge/false-contradiction story, but lenses/cycle consistency are existing methods. The paper-level contribution would be the scientific typed application and its measured value, not the mathematics itself.

## P4 — **performance helper, not a novelty centerpiece**

A `DefeaterPlanner` can choose the next protected evidence/check based on expected unresolved authority-risk reduction per cost. It must remain separate from authority transition: selected evidence action means `BLOCKED: gather evidence`, never `AUTHORIZED`.

PCAA, semantic quorum and defeater work already occupy nearby novelty. Do not edit the current P4 protocol while #128 is active. If used later, evaluate it as an efficiency/coverage helper.

## P5 — **strong governance/performance candidate, but update nearest work first**

PACE (arXiv:2606.08106) directly absorbs anytime-valid acceptance tests for self-evolving agents. P5 should not claim this.

The surviving ORION-specific direction is a non-compensatory evidence ladder:

`STATIC -> REPLAY -> INDEPENDENT FRESH -> PROTECTED`

- early failure saves expensive evaluation;
- replay gains cannot compensate fresh harm;
- protected `CANNOT_CHECK` cannot become promotion;

Before P5's nearest-work closure is accepted, PACE should be explicitly dispositioned by the active P5 lane.
