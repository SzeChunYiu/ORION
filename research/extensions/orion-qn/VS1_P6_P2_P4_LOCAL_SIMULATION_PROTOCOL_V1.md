# ORION-QN VS1 — P6-Q + P2-Q + P4-Q local-simulation protocol v1

Status: **PROSPECTIVELY FROZEN BEFORE RESULT-BEARING IMPLEMENTATION/OUTCOMES**  
Programme: `SzeChunYiu/ORION#734`  
Parents:
- `ORION_QN_PROVENANCE_BOUNDARY_V1.md`

Evidence mode for the first execution: `LOCAL_SIMULATION` plus analytic/query accounting.  
Physical quantum-speedup claim permitted from this protocol: **NO**.

## 1. Why this vertical slice is first

VS1 couples three ORION responsibilities without requiring the whole framework to be quantumized:

- **P6-Q semantic mechanics:** define the admissible quantum/classical transition and its typed obligations;
- **P2-Q discovery/search:** execute a bounded candidate-search mechanic where established quantum search algorithms provide a clean theorem-level comparison;
- **P4-Q verification:** independently reconstruct whether the returned candidate actually satisfies the original predicate and whether all execution/access/resource obligations were met.

This is intentionally earlier than P5/P9/P10 self-optimization. It tests the semantic and evidence spine before learned routing or method invention can add confounders.

## 2. Primary research question

> Can ORION-QN represent and locally execute genuine quantum search kernels while preserving the exact scientific problem, access contract, measurement semantics, strongest fair classical comparator and bounded claim authority — including hostile regimes where a query advantage is real but end-to-end quantum value is not?

The desired result is **discrimination**, not universal quantum preference.

## 3. Pre-registered claim ceiling

VS1 may support only one or more of:

```text
QUANTUM_SEMANTICS_DEFINED
QUANTUM_FEASIBLE_NO_ADVANTAGE
QUANTUM_QUERY_ADVANTAGE_ONLY
CLASSICAL_PARENT_SUFFICIENT
CANNOT_CHECK_ACCESS_MODEL
INVALID
```

If a separate Microsoft-QRE or equivalent FT projection is later added under a frozen resource model, it may support `QUANTUM_PROJECTED_FT_ADVANTAGE` for that projected regime.

VS1 local simulation alone can never support `QUANTUM_END_TO_END_ADVANTAGE_SUPPORTED`.

## 4. Frozen benchmark families

### S1 — unstructured finite admissible-candidate search

Object:

```text
X = {0, ..., N-1}, N = 2^n
predicate f: X -> {0,1}
M = {x : f(x)=1}
return one x in M, or the declared no-solution terminal when permitted
```

Initial known-solution subfamilies:

- `S1A_SINGLE`: exactly one marked candidate;
- `S1B_MULTI`: marked count `k` in a frozen small set where the selected amplitude-amplification variant’s assumptions are satisfied;
- `S1C_NO_MARKED`: negative/edge control; it must not be silently treated as the one-solution case.

Quantum donor: Grover/amplitude amplification.  
Primary source: https://arxiv.org/abs/quant-ph/0005055

Classical baselines:

- `C1_EXHAUSTIVE_ORDERED`: deterministic scan in frozen order;
- `C2_RANDOM_WITHOUT_REPLACEMENT`: randomized scan with frozen seed schedule where applicable;
- `C3_PRECOMPUTED_INDEX`: only in S4, where preprocessing/reuse is part of the registered workload.

The quantum route and classical baselines receive the same predicate semantics. If a reversible/coherent oracle requires extra construction not needed by a classical predicate call, that construction is charged to the quantum route.

### S2 — structured/backtracking search

Object: a bounded constraint-search tree generated by a deterministic backtracking procedure.

Quantum donor: Montanaro-style quantum walk speedup of backtracking under theorem-specific assumptions.  
Primary source: https://arxiv.org/abs/1509.02374

Frozen rule:

- do **not** call an arbitrary SAT/CSP solver “the quantum backtracking baseline”;
- first construct the exact classical backtracking tree/test model required by the selected theorem/implementation;
- count tree/test access and all coherent-test implementation costs separately;
- if the implementation cannot faithfully instantiate the theorem assumptions, terminal is `CANNOT_CHECK_ACCESS_MODEL`, not an inferred speedup.

S2 implementation is allowed after S1 contract conformance is green; it is not required to make S1 scientifically valid.

### S3 — expensive-oracle hostile family

Purpose: demonstrate that fewer oracle calls do not imply lower end-to-end cost.

Start from S1A semantics but assign explicit oracle costs:

```text
B_q = one-time coherent oracle construction cost
q_q = number of quantum oracle/inverse calls
c_q = per-call coherent implementation cost

B_c = classical preprocessing/build cost
q_c = number of classical predicate calls
c_c = per-call classical predicate cost
```

Report at minimum:

```text
query_only_quantum = q_q
query_only_classical = q_c

oracle_layer_quantum = B_q + q_q*c_q
oracle_layer_classical = B_c + q_c*c_c
```

No wall-clock “quantum win” may be inferred from the local simulator runtime.

Frozen hostile regimes must include at least:

1. `ORACLE_CHEAP`: construction/per-call costs do not dominate and the query-model advantage should remain visible;
2. `ORACLE_BUILD_DOMINANT`: coherent-oracle construction is large enough to erase the query reduction at the registered one-shot workload;
3. `ORACLE_CALL_DOMINANT`: coherent call/inverse implementation is materially more expensive than the classical predicate call.

The exact numeric cost schedule must be frozen in the implementation packet before result aggregation.

### S4 — classical-index / amortization hostile family

Purpose: test repeated-use workloads where a classical index can be built once and reused.

Register workload horizon `R` = number of independent queries against the same underlying admissible candidate universe/data.

Compare:

```text
classical total(R) = index_build + R * indexed_query
quantum total(R)   = q_state/oracle_build + R * quantum_query_work
```

The benchmark must include:

- small `R`, where preprocessing may not amortize;
- crossover-adjacent `R`;
- large `R`, where a classical index can dominate if the scientific problem permits reusable preprocessing.

If the quantum route is allowed to reuse state/oracle construction, the classical route receives analogous allowed reuse. If destructive measurement forces repreparation, that cost remains visible.

## 5. Frozen size ladder

The initial exact local-simulation ladder is:

```text
n = 3, 4, 5, 6, 7, 8, 9, 10
N = 2^n
```

Rationale:

- small enough for deterministic exact/local verification on ordinary computers;
- large enough to expose the expected square-root query trend without pretending to test fault-tolerant scale;
- leaves room for hostile cases and repeated seeds without turning CPU statevector simulation cost into the target metric.

A later scale-up may add simulator methods or larger `n`, but that becomes a new packet and cannot rewrite this protocol’s outcome.

## 6. Frozen subject generation

For each `n` in S1A:

- generate at least 8 marked positions using a deterministic seed schedule;
- include edge positions `0` and `N-1` as known-answer cases;
- keep marked position independent of the classical ordered scan when reporting aggregate query counts;
- record seed, marked set and generator version in the receipt.

For S1B:

- use frozen marked-count values selected before execution;
- generate marked sets deterministically from recorded seeds;
- record which amplitude-amplification variant handles known/unknown `k` and do not mix their claims.

For S1C:

- include explicit zero-solution worlds;
- use only an algorithm/terminal whose assumptions permit correct no-solution handling.

No post-outcome deletion of inconvenient marked positions or seeds.

## 7. Primary metrics

### Semantic/correctness metrics

- returned candidate satisfies the original predicate;
- no false positive on no-solution controls;
- measured distribution agrees with independent simulator/analytic expectation within frozen tolerance;
- classical and quantum routes solve the same `QProblemContract`;
- state-preparation/oracle/measurement contracts validate;
- independent P4-style reconstruction reproduces final bounded result.

### Query metrics

- classical predicate calls;
- quantum oracle calls;
- quantum inverse-oracle calls where applicable;
- state-preparation calls;
- repetitions/shots.

Query metrics are reported as separate coordinates, not combined with CPU simulator time.

### Logical program/resource metrics

Where obtainable without inventing physical assumptions:

- qubits;
- ancillae;
- logical gate counts/depth;
- two-qubit gate counts/depth after a frozen transpilation basis;
- oracle construction gates;
- state-preparation gates;
- measurement shots;
- classical preprocessing/reconstruction time.

### Local computer metrics

CPU/GPU wall time and peak memory may be recorded as **simulator engineering metrics only**. They are explicitly excluded from any quantum-vs-classical physical-speedup decision.

## 8. Frozen classical fairness rules

1. same semantic problem and tolerance;
2. same visible dataset/predicate information;
3. classical code may exploit ordinary classical representation of the supplied input;
4. quantum route pays to turn that representation into coherent state/oracle access unless such access is natively supplied by the problem;
5. classical preprocessing/indexing is allowed whenever the workload definition permits it;
6. quantum preprocessing/reuse is allowed under the same workload horizon and must be recorded;
7. no weak “naive loop only” headline when a stronger exact/classical baseline is applicable;
8. dequantized/sample-query baselines become mandatory for later P3/P9-style vector/data problems; they are not artificially forced into finite Boolean-search S1 when their access model is irrelevant.

## 9. Oracle semantics for S1

The first oracle must implement a Boolean predicate under an explicit reversible embedding such as:

```text
U_f |x>|b> = |x>|b xor f(x)>
```

or a phase oracle with a documented equivalence construction.

Receipt records:

- source predicate representation;
- reversible/phase construction;
- ancilla use;
- inverse implementation;
- controlled form if used;
- logical cost;
- whether the same predicate is callable classically without coherent construction.

A hand-authored diagonal matrix that directly encodes hidden gold is allowed only as a **semantic known-answer oracle fixture**, never as an end-to-end cost baseline unless the problem contract natively supplies that matrix/oracle.

## 10. Local simulator policy

Initial adapter target: Qiskit Aer/current local Qiskit simulation, version pinned by the result-bearing implementation commit/environment manifest.

Current official guidance used at protocol freeze:

- https://quantum.cloud.ibm.com/docs/en/guides/local-simulators
- https://quantum.cloud.ibm.com/docs/en/guides/simulate-with-qiskit-aer

The implementation may choose an exact statevector or another exact method for S1. The method and version must be in `QBackendIdentity.v1`.

Noise-model runs, if added, are secondary robustness evidence. They do not transform simulation into hardware evidence.

## 11. Measurement policy

The S1 scientific output is a classical candidate index or no-solution terminal. The frozen measurement contract must therefore specify:

- computational-basis measurement of the search register;
- shot count or exact sampling mode;
- selection rule from measured outcomes;
- independent predicate re-check of the selected candidate;
- treatment of failed shots/repetitions;
- confidence/success threshold if a stochastic success-rate claim is made.

The verifier may inspect simulator internals for debugging only when that inspection is not used as scientific evidence. Result-bearing scoring uses the frozen measurement output.

## 12. P4-Q independent reconstruction

For every result-bearing run, reconstruct from artifacts rather than trusting executor success:

```text
QProblemContract
  -> QAccessContract
  -> QStatePreparationContract
  -> QOracleContract
  -> QProgramIR/kernel identity
  -> QBackendIdentity
  -> QMeasurementContract
  -> raw measurement digest
  -> returned candidate
  -> independent predicate verification
  -> QResourceReceipt
  -> QVerificationReceipt
  -> QuantumReceipt
  -> claim ceiling
```

The reconstruction code/path must not import a precomputed PASS flag from the executor.

## 13. Hostile tests frozen before implementation

The first implementation must include or explicitly schedule these RED cases:

1. oracle marks the wrong item;
2. oracle has correct answer but uses hidden gold stronger than the admitted input;
3. state preparation silently reads hidden evaluator state;
4. simulator statevector maximum-amplitude index is used instead of measurement;
5. inverse/uncomputation omitted and output distribution changes;
6. marked count violates algorithm assumption;
7. no-solution world incorrectly returns an item;
8. classical baseline is given a different predicate order/information;
9. oracle construction cost is zeroed only for the quantum route;
10. measurement/shots omitted from resource receipt;
11. CPU simulator wall time labeled quantum runtime;
12. logical resource estimate labeled physical hardware resource;
13. backend version changes while stale receipt is replayed;
14. quantum execution fails/does not fit local resources and system records scientific refutation instead of fallback/CANNOT_CHECK;
15. quantum result attempts to set P8 novelty/validity/adoption authority directly.

No-alarm controls must include a fully admissible small S1A instance that completes end-to-end through receipt reconstruction.

## 14. Pre-registered interpretation table

| Observation | Allowed interpretation |
|---|---|
| correct simulated Grover/amplitude-amplification behavior + expected oracle-call scaling | `QUANTUM_QUERY_ADVANTAGE_ONLY` if matched query assumptions hold |
| correct quantum circuit but no meaningful query/resource advantage | `QUANTUM_FEASIBLE_NO_ADVANTAGE` |
| stronger classical route dominates | `CLASSICAL_PARENT_SUFFICIENT` for registered regime |
| coherent oracle/state cannot be derived under admitted access | `CANNOT_CHECK_ACCESS_MODEL` or `INVALID` |
| local simulator too expensive for a requested size | engineering limit / fallback; not scientific negative |
| projected FT estimate later beats classical model under frozen assumptions | at most `QUANTUM_PROJECTED_FT_ADVANTAGE` until real hardware evidence |
| local simulator finishes faster than Python baseline | **no physical quantum-speedup claim** |

## 15. Stop/reopen rules

VS1 S1 can close as a semantic/query-model tranche when:

- known-answer and hostile conformance tests execute;
- the quantum kernel and strongest applicable classical baseline solve the same contract;
- every result has a reconstructable `QuantumReceipt`;
- query advantage, when reported, matches the theorem/access assumptions;
- simulator evidence is not laundered into hardware evidence;
- all unresolved Q1 vetoes are explicit.

Reopen if:

- a stronger classical baseline changes the interpretation;
- a hidden access/preparation cost is discovered;
- the oracle implementation does not match the declared semantics;
- backend/compiler changes invalidate receipts;
- protected hostile tests find fail-open authority behavior.

S2–S4 remain mandatory programme stress families even if S1 is green. A positive S1 does not establish ORION-QN end-to-end advantage.
