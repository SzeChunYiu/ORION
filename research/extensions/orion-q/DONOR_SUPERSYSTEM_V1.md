## Purpose

ORION-Q does not compare itself against isolated papers. The incumbent is the strongest faithful composition of current specialist quantum discovery systems. Each donor below is absorbed as a capability with explicit preconditions, outputs, costs, verifier assumptions and failure modes.

## Typed donor capability contract

Every donor capability admitted to the ORION-Q incumbent must expose:

- `capability_id` + source/version;
- supported problem/task class;
- required representation;
- required access/oracle model;
- required input/specification language;
- output type;
- correctness/verifier contract;
- resource vector / evaluation cost;
- adaptive feedback consumed;
- reusable abstraction or library state produced;
- known failure modes;
- applicability boundary;
- whether it can modify its own search/method language;
- whether it can change representation/access model;
- whether it can carry formal/resource authority;
- whether it can transfer learned research operators across domains.

## Donor-composed incumbent graph

The initial super-system should expose the following composition routes:

1. `problem -> representation/access analysis -> donor specialist selection`;
2. `specialist proposal -> cheap verifier -> expensive verifier -> resource estimator`;
3. `verified successful traces -> library/DSL abstraction learner`;
4. `failed traces -> scoped failure store -> reopen/abstain/verify decision`;
5. `candidate theorem/conjecture -> formal proof tool`;
6. `candidate quantum stack -> oracle/state-preparation/resource closure`;
7. `candidate QEC design -> code proxy -> syndrome circuit -> decoder evaluation`;
8. `candidate algorithm route -> QSVT/simulation/compiler family -> AutoQuREO-style stack optimization`.

The donor-composed baseline may use all of these routes. ORION receives no credit merely for wiring them together.

## Candidate ORION-only residuals after absorption

These are hypotheses to test, not novelty claims:

### R1 — shared cross-domain epistemic state
One typed failure/provenance/resource/authority state improves decisions across specialist boundaries and held-out quantum domains.

### R2 — cross-domain research-operator transfer
A research operator learned in one domain (e.g. scoped reopening, verifier staging, representation diagnostic) improves another domain without target-specific retuning.

### R3 — obstruction-triggered capability-space edit
When no donor capability is admissible/sufficient, ORION identifies the responsible layer and proposes a representation/interface/method-language edit rather than only retuning a supplied tool.

### R4 — proof-carrying end-to-end method evolution
The edit is promoted only if it preserves original problem semantics/access and closes correctness/error/resource obligations.

### R5 — recursive negative recovery
A failed ORION candidate automatically becomes a new bounded research object; the system absorbs the mechanism that defeated it and attacks the next residual.

## Strong-baseline rule

For each experiment compare against the strongest feasible composition of donors, not a weakest-common-denominator implementation. If an ORION mechanism merely recreates a donor behavior, absorb it and move upward.

## Current maximal target

`MAX_R6_NEW_QUANTUM_METHOD_OR_RESULT` remains the programme endpoint:

A frozen ORION-Q system produces an independently verified reusable quantum method, representation, theorem/bound, design principle or algorithmic construction that the donor-composed incumbent does not obtain at matched budget.

Lower MAX rungs are evidence milestones and do not terminate the programme.
