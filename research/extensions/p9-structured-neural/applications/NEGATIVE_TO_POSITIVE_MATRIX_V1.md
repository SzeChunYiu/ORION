# P9 negative-to-positive matrix V1

Status: research synthesis / no new positive authority.

Doctrine:

`NEGATIVE FINDING -> RESPONSIBILITY -> DONOR ESSENCE -> MINIMUM REPAIR -> FROZEN FALSIFIER -> APPLICATION CONSEQUENCE`.

A historical negative is never relabelled positive. A positive successor must run under a new protocol and preserve the negative as its control.

## N1 — topology is non-identifying when relation semantics matter

**Observed P9 boundary**

The relation-semantics hostile pair is intentionally identical through topology but requires different mechanic choices. More graph depth cannot recover a relation type that is absent from the input.

**Responsibility**

Representation / information, not model capacity.

**Donor essence to absorb**

- HGT / typed relation-specific attention: relation/node typing is a standard and useful inductive bias, not P9 novelty.
- Graph-guided Kubernetes RCA (arXiv:2606.08590): typed evidence graph + deterministic traversal/tool operations can support auditable incident diagnosis, while its authors explicitly retain benchmark-coupled limitations rather than claiming broad production success.
- CT-Repair (arXiv:2607.12605): static Code Property Graph plus Temporal Execution Graph and multiple evidence perspectives improve program repair over raw/less structured evidence.

**Minimum positive repair**

Expose only externally grounded relation semantics. Compare topology-only, typed-relational, and same-information serialized views before changing model scale.

**Falsifier**

If same-information serialization or a strong topology model matches typed relational performance on reminted held-out families, there is no special structural-inductive value to claim.

**Application consequences**

Highest priority: SRE/root-cause diagnosis and program repair. Also process/workflow conformance and formal proof dependencies.

## N2 — typed structure is non-identifying when the actual transformation is hidden

**Observed P9 boundary**

Typed transport endpoints do not determine GLUE vs OBSTRUCTION. The actual affine map values are required.

**Responsibility**

Missing transformation information.

**Donor essence to absorb**

- Knowledge Sheaves / Neural Sheaf Diffusion: local spaces and relation-specific restriction/transport maps are established objects.
- P9 A5 result: when complete affine maps are visible, exact composition solves the bounded atom and fails closed when maps are missing/ambiguous.

**Minimum positive repair**

Separate `map proposal/estimation` from `map composition/checking`. Use learning only for the uncertain former; use exact algebra for the latter whenever possible.

**Falsifier**

If a learned end-to-end model is more reliable/resource-efficient than the hybrid at matched information on a protected noisy-map task, the exact-first rule narrows.

**Application consequences**

Multi-representation scientific/engineering data, schema/version migrations, coordinate/unit transforms, proof-state or program-representation transports, and any workflow where known transformations compose.

## N3 — current state is non-identifying when relevant negative history is hidden

**Observed P9 boundary**

Failure-history hostile pairs are identical through CURRENT and separate only when admitted history is visible.

**Responsibility**

State abstraction omitted a load-bearing temporal coordinate.

**Donor essence to absorb**

- failure-learning/selective replay and continual-memory work already establishes value from past failures;
- STRACE (arXiv:2607.07702) shows structural trajectory/root-cause extraction can improve agent optimization and reduce noisy trace burden;
- CT-Repair uses validation feedback to refine structured repair strategies.

**Minimum positive repair**

Attach failure to the smallest justified scope: mechanic + binding/context + evidence + reopen conditions. Do not turn `failed once` into a permanent global ban.

**Falsifier**

Compatible history should reduce repeat dead ends; intentionally stale/incompatible history must not cause harmful avoidance. A raw transcript-memory or selective-replay baseline gets the same past information.

**Application consequences**

Program repair, SRE remediation histories, long-running research agents, robotics skill failures, and repeated workflow exceptions.

## N4 — neural inference is unnecessary on the D0 affine gluing atom

**Observed P9 boundary**

A5 gives exact bounded inference once the necessary maps are present.

**Responsibility**

The residual is deterministic computation, not learning.

**Donor essence to absorb**

- Learning Symbolic Operators for TAMP (arXiv:2103.00589) demonstrates the value of explicit symbolic abstractions for planning and reports strong performance relative to several model-free GNN baselines in its domains.
- STRATUS (arXiv:2506.02009) combines specialized agents with a state machine and explicit safety specification rather than treating one neural model as the whole control system.
- graph-guided RCA similarly combines learned reasoning with deterministic graph/tool operations.

**Minimum positive repair**

Hybrid computation: neural/perceptual proposal where the world is uncertain; exact/search/constraint computation where semantics are known.

**Falsifier**

At matched evidence and compute, an end-to-end learned model must beat the hybrid on protected task validity, false closure, and resource use—not merely on a proxy score.

**Application consequences**

Robotics/TAMP, formal proof/search, process conformance, software dependency checking, scientific constraint systems.

## N5 — broad natural-science structure is not trustworthy gold yet

**Observed P9 boundary**

A6 closes `EXACT_TRACE_DATA_ONLY`. P1/P3 did not manufacture the previously imagined expert/natural-paper corpus.

**Responsibility**

Data authority / annotation reliability.

**Donor essence to absorb**

- ITBench provides reproducible real-world-inspired IT scenarios and interpretable evaluation metrics; its initial paper reports low success of existing agents, making it a useful stress environment rather than an easy benchmark.
- Defects4J provides reproducible real software bugs, but recent reproducibility analysis (arXiv:2604.26674) warns that benchmark execution/test adequacy itself must be audited.
- OCEL 2.0 explicitly represents events, objects, changing attributes, object relations, event-object relations and qualified roles, providing structure-native process data rather than retrospective reasoning labels.
- Lean/Mathlib proof states provide native formal structure and checking.

**Minimum positive repair**

Move ecological validation first into structure-native domains. Treat natural-language scientific extraction as proposal + provenance + independent adjudication, not automatic gold.

**Falsifier**

If application performance disappears once native structured inputs are replaced by independently extracted real-world structure, the bottleneck is extraction/data authority, not the P9 computation substrate.

**Application consequences**

Deployment order: software/SRE -> formal proof -> process/workflow -> robotics -> only then broad natural-science method extraction.

## N6 — latent, explicit binding and causal branches are not load-bearing for bounded P9

**Observed P9 boundary**

A3/A9/A10 were closed as not load-bearing/deferred for the current paper, not experimentally refuted in general.

**Responsibility**

Scope / absence of a discriminator requiring the mechanism.

**Donor essence to absorb**

- Coconut/recurrent latent reasoning owns much of non-language recurrent computation;
- Neural Production Systems and Transformer-binding work own major rule/entity binding mechanisms;
- Mechanistic/causal world-model work owns mechanism-centric and intervention-stable modularity directions.

**Minimum positive repair**

Triggered reopening only.

- reopen latent compute when matched explicit/search computation cannot solve a protected adaptive/recurrent task;
- reopen binding when a reusable operator must ground typed roles to unseen entities/counts;
- reopen causal mechanics when passive observations are insufficient and interventions distinguish candidate effects.

**Falsifier**

Each reopened mechanism must beat the strongest donor-native baseline and the simpler P9 state/inference stack on the exact trigger task.

**Application consequences**

Robotics is the clearest joint trigger for binding + causal effects; long-horizon interactive agents may trigger latent recurrence. These belong downstream unless a P9 structure-native pilot isolates the mechanism cleanly.

# Real-world application priority

## A1 — SRE/root-cause diagnosis — RUN FIRST

Why:
- exact incident/fault scenarios exist;
- typed resource/service/dependency graphs are native;
- model outputs can be evaluated for root-cause entity, propagation and localization;
- missing evidence can be intentionally registered as UNRESOLVED;
- current donor systems already supply strong graph-guided baselines.

Frozen design: `applications/A1_SRE_DESIGN_PROTOCOL_V0.json`.

## A2 — program repair — RUN AFTER A1

Use Defects4J or a stricter audited subset. Structural views should include static code graph, dynamic execution graph, failure/test evidence and prior attempted repairs. Preserve benchmark-invalid/underspecified cases rather than treating every test-suite pass as correctness.

## A3 — formal proof — LOW-COST EXACT SECOND DOMAIN

Use exact Lean states, expression/dependency graphs, candidate atomic tactics, native verification, reminted identifiers and failure-history ablations. Nazrin-class graph theorem proving is a donor/baseline.

## A4 — object-centric process/workflow diagnosis

Use OCEL 2.0/native object relations and held-out process families. Compare flattened event sequence, object topology, typed/qualified relations, and typed+conformance inference. Object-centric anomaly literature already warns that flattening can create artifacts, making this a natural P9 discriminator.

## A5 — robotics/TAMP — TRIGGERED SECOND WAVE

Use only after A1-A4. It is resource-heavy but supplies the cleanest reasons to reopen role binding, uncertain effects and causal/interventional mechanics.

# Paper consequence

The current P9 manuscript may claim a **design implication**, not application performance:

> P9's negative results suggest a hybrid deployment principle: expose load-bearing structure explicitly; learn only the uncertain coordinates or rankings; apply exact/search computation when the semantics are known; preserve unresolved state when decisive information is absent; and validate first in structure-native domains.

No root-cause, repair, proof, workflow or robotics performance number is a P9 result until its own prospective protocol executes and is independently verified.
