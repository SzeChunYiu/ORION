## Candidate terminal

`REPRESENTATION_INVENTION_NO_INCREMENTAL_VALUE`

This is a bounded **negative incremental-value** result if the exact frozen primary/replication packet and independent reconstruction survive repository CI.

It makes two claims that must be kept separate:

1. **registered representation change is genuinely required** on the 48 positive worlds across primary + replication because exact exhaustive enumeration proves that no hypothesis in the frozen old language satisfies the full explanatory/counterfactual contract;
2. **ORION adds no protected value beyond the strongest verified regime-revision parent** because that parent receives the same public information, move library, experiment budget, correspondence obligations and validation interface and is required to make exactly the same decisions with the same metrics.

The result therefore supports neither `SEARCH_HARD_NOT_JUMP` nor `ZERO_ERROR_JUMP_SUPPORTED` as an ORION-specific superiority claim.

## 2. Finite old-language impossibility is the key discriminator

Each invented world contains an evaluator-side finite old-language hypothesis list.

For every positive case:

- public observed-regime error of the incumbent is exactly zero;
- every old-language candidate matches the registered public signature;
- **zero** old-language candidates match the protected full-contract signature.

For every no-Jump control:

- at least one old-language candidate matches the full contract;
- the `SEARCH_HARD_BUT_EXPRESSIBLE` control deliberately places the full solution last in the enumeration.

The benchmark can therefore distinguish:

```text
old language has no registered full-contract solution
```

from

```text
old-language solution exists but search is inconvenient
```

without inferring impossibility from a candidate's search failure.

This is a finite registered expressivity claim only. It is not a proof that the representation move is impossible in every richer encoding of the old scientific concepts.

## 3. Zero-error positive families

Each split contains four opaque variants of six structural families:

- zero-error local-theory unification -> `BRIDGE_CORRESPONDENCE`;
- counterfactual observer/frame change -> `FRAME_COORDINATE`;
- hidden transformation invariant -> `INVARIANT_ORBIT`;
- relational/path lift -> `RELATIONAL_LIFT`;
- intervention-induced causal/contextual split -> `CAUSAL_SPLIT`;
- typed bridge law between exact local descriptions -> `BRIDGE_LAW`.

Opaque case/object/relation names are generated from the split seed. Historical scientific names are banned from public/gold structural symbols.

The six labels are benchmark move classes, not claims of a universal creativity taxonomy.

---

## 4. No-Jump controls

Each split also contains three opaque variants of:

- parameter update sufficient;
- fixed-language structure sufficient;
- additional evidence sufficient;
- no change needed;
- measurement repair sufficient;
- search hard but expressible.

A false representation change on any control is a failure. This prevents a candidate from winning merely by proposing a novel representation everywhere.

## 5. Candidate-visible information and anti-retrieval boundary

Candidate policies receive a `PublicJumpCase.v1` containing only:

- opaque identities;
- public observations and exactly matching incumbent predictions;
- old-language **public** signatures;
- registered thought-experiment menu and one selected outcome;
- frozen representation move library;
- correspondence obligations;
- public verification interface identities.

The candidate does not receive:

- positive/control family identity;
- gold move;
- protected full-contract signatures;
- protected consequence token;
- old-language gold solution identity;
- terminal label.

This is a process-level anti-leakage boundary for the finite repository benchmark. It is not a cryptographic secrecy claim against a malicious reader of a public repository.

## 6. Non-compensatory Jump success

A positive candidate passes only if all gates pass:

1. exact old-regime insufficiency;
2. Jump requested;
3. correct structural representation move;
4. informative thought experiment selected;
5. complete correspondence/preservation;
6. protected novel consequence predicted before evaluator access;
7. no scientific/adoption self-authority.

The `ORION_NO_CORRESPONDENCE` ablation is intentionally able to choose the correct experiment, move and protected consequence while still scoring **zero** positive Jump successes. This makes preservation/correspondence load-bearing rather than a presentation field.

It is not intentionally weakened. It receives the same:

The frozen target requires both the strong parent and `ORION_JUMP` to achieve per split:

- zero false Jumps;
- 24/24 old-regime-insufficiency recognitions;
- 24/24 correspondence successes;

- 24/24 informative thought experiments;

Their complete decision vectors and all metrics must be identical on both primary and replication. ORION's incremental protected gap is frozen at exactly zero.

This is the core reason for the candidate terminal.

## 8. Other comparator interpretation

`OLD_DSL_EXHAUSTIVE`, `M_OPEN_SAME_REPRESENTATION`, and `FIXED_REP_WORLD_MODEL` can correctly establish the registered representation ceiling and avoid false Jumps on all controls, but cannot cross the frozen representation type on positive cases.

That is not evidence that symbolic search, M-open discovery or mechanistic world models are weak methods. It only defines the registered positive cases so their old/same-representation action spaces are formally insufficient.

LLM/RAG comparators without stable executable model/credential bindings are retained as `MECHANISM_COMPARATOR_ONLY`, not presented as quantitative losers.

## 9. Thought-experiment sensitivity

The thought-experiment outcome is load-bearing. Hostile tests modify an informative frame-change outcome to one structurally indicating a bridge relation and require both the strong parent and ORION to change their representation proposal accordingly; the changed proposal then fails the original protected structural contract.

Thus the candidate cannot be a fixed proposal table that ignores the registered epistemic experience.
