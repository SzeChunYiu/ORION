## 5. Why failure history is still useful

The intended negative result is not `failure memory does nothing`.

### Compatible recurrence

No-history repeats the same cheap failed route in E1. Scoped parent/ORION apply the validated local nogood and choose the still-live alternative.

### Changed context

Permanent global ban breaks E2/E7 by treating repaired measurement or a new regime as identical to the old failed context. Scoped parent/ORION reopen or make the old negative inapplicable.

### Semantic preservation

Exact string/context equality breaks E3 by reopening on a semantics-preserving representation rename. P7 complete transport preserves the old negative despite nonidentity.

### Invalid execution/measurement

E4 explicitly blocks the inference `execution failed -> scientific theory false`. The responsibility gate precedes scientific reuse of the negative.

### Failure to next question

E5 turns a plural responsibility state into a decision-relevant discriminating test. The ORION arm receives no special credit for this: #477/value-of-information/metareasoning is the parent owner.

### Honest unresolved

E6 has no admissible discriminator. Both parent and ORION must return `UNRESOLVED`, not query for zero decision value and not close by global ban.

### Broken-shut control

E7 proves that failure history can be harmful if applied by surface/method identity across incompatible regimes. Success-only/no-memory is allowed to beat naive negative memory here.

### Publication/visibility distortion

E8 exposes an incomplete outcome archive. Parent/ORION may flag `DISTORTION_SUSPECTED` but may not fabricate the missing negative outcomes or globally promote visible successes.

## 6. Why the strong parent should match ORION

The prior programme already decomposed the load-bearing semantics:

- #517/F2: scoped negative conflict content reduces to TMS/ATMS/nogood structure plus scientific responsibility/evidence/authority;
- #518/F3: semantic applicability/reopening reduces to P7 transport;
- #477: selecting the next decision-relevant test/computation is owned by active inquiry/value-of-information/metareasoning parents;
- #509: source/cutoff/visibility chronology is owned by the failure-atlas/evidence substrate.

`FailureKnowledge.v1` remains useful as a typed ORION interchange/storage contract. It is not promoted into a new scientific inference primitive.

The executable benchmark therefore implements the strong parent independently and requires its **decision vector and all metrics** to match `ORION_SCOPED_FAILURE` exactly.

## 7. Post-design saturation

Two fresh primary-source rounds were run after the benchmark/expected packet was frozen.

### Round 1 — continual memory / transfer / metareasoning

- Meng et al., arXiv:2607.15587: replay transfer should be compatibility-selective, reinforcing negative-transfer gating;
- Dorovatas et al., arXiv:2603.01761: modular memory is an established parent for continual experience accumulation;
- De Sabbata, Sumers & Griffiths, arXiv:2410.05563: rational metareasoning/value of computation owns cost-aware inference-time compute selection.

Result: `NO_MATERIAL_CHANGE`.

### Round 2 — failure-driven agents / trace diagnosis

- Sun et al., arXiv:2606.31270: failed trajectories can be turned into useful inference-time repairs;
- Chen et al., arXiv:2606.06324: trace-aware responsibility localization supports scoped harness repair rather than broad changes;
- Yin, Li & Wang, arXiv:2605.11882: verifier-scored failed trajectories can drive corrective supervision under multiple safety/utility gates.

Result: `NO_MATERIAL_CHANGE`.

These sources strengthen the proposition that failures are useful data while continuing to assign storage, compatibility, responsibility, repair and inquiry semantics to mature parent families.

## 8. Non-compensatory gates

No weighted score can compensate for:

- a scientific-authority violation;
- a false global exclusion;
- repeating an old dead end when the scoped negative applies;
- silently keeping an old negative after verified semantic change;
- reopening a valid negative merely because a surface name changes when complete transport exists;
- choosing a zero-value query when no discriminator exists;
- fabricating missing negative outcomes from an incomplete publication corpus;
- ORION receiving more information/resources than the standard parent.

## 9. What this closes and what it preserves

If the frozen exact-head benchmark and saturation checks survive repository CI, the scientifically appropriate #508 disposition is:

`FAILURE_MEMORY_USEFUL_BUT_STANDARD_METHODS_SUFFICIENT`.

### Keep

- `FailureEpisode.v1` source-grounded history/cutoff/visibility substrate;
- `FailureKnowledge.v1` typed scoped negative record;
- compatibility/reopen semantics;
- P7 complete/incomplete transport;
- #477 decision-relevant inquiry;
- historical negative/null/failure corpora as first-class research inputs;
- negative-transfer / broken-shut controls.

### Strike

- novelty for `learn from failure`;
- a universal ORION failure ontology/calculus at this resolution;
- a standalone staleness atom when P7 transport decides the semantics;
- a standalone extraction primitive when ATMS/nogood + responsibility decides the scope;
- a standalone inquiry primitive when standard information-value/metareasoning parents match it.

### Reopen only for a narrower residual

A future result may reopen the programme if, under matched public information/resources, ORION exhibits a scientific failure-learning capability that the frozen strong parent cannot reproduce—e.g. a cross-domain scope/transport/inquiry interaction with genuine protected incremental reach.

## 10. Nonclaims

A green 32-case finite study does not establish:

- universal real-world scientific failure-learning benefit;
- external deployment safety;
- population-frequency claims from the historical atlas;
- that all negative outcomes are published/available;
- that `FailureKnowledge.v1` can infer correct exclusions from raw observations;
- novelty of failure memory, selective replay, truth maintenance, transport or metareasoning;
- #500/#501 Jump competence;
- independent #283 verification or #287 novelty.
