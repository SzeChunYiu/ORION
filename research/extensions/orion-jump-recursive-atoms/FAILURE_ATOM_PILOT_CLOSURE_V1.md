# F1 — silent failure observability

## Formal countermodel

Let a registered public observation history be `h`. Construct two admissible worlds `W_valid` and `W_fail` such that every field visible to a domain-general public-only detector is identical:

```text
Obs(W_valid, h) = Obs(W_fail, h)
```

but the protected semantic validity differs:

```text
MaterialFailure(W_valid) = false
MaterialFailure(W_fail) = true.
```

Any deterministic detector `D` whose input is only the registered public observation receives the same input in both worlds, so

```text
D(Obs(W_valid,h)) = D(Obs(W_fail,h)).
```

It therefore cannot correctly emit different material-validity labels for both worlds. A sound system must either acquire an additional discriminator whose semantics separate the worlds or remain unresolved.

This is not an argument that failure cannot be detected. It is an argument that **the decisive observation is owned by the relevant semantic verifier**, not manufactured by a universal public-trace classifier.

## Frozen separating families

The executable packet uses four pairs:

1. plausible numerical output with hidden valid vs violated physical invariant;
2. same high evaluator score with intact vs compromised custody/protocol;
3. same plausible derivation surface with native proof checker accept vs reject;
4. same locally accepted steps with globally consistent vs inconsistent composition.

Each pair records a distinct additional discriminator:

- native physical invariant check;
- protected custody/protocol audit;
- native proof verifier;
- cross-step semantic consistency check.

The detector is explicitly forbidden from reading the protected material-failure label.

## Parent pressure

Recent end-to-end research-agent evaluations reinforce the need for process/artifact visibility rather than only final success, but they do not supply a universal semantic oracle:

- Fei et al., *How Do Agents Fail on AutoResearch*, arXiv:2608.14905;
- Zhan et al., *Why Your Deep Research Agent Fails?*, arXiv:2601.22984;
- Xu et al., *ResearchClawBench*, arXiv:2606.07591.

A stronger constructive parent is domain-verifier composition:

- Deng et al., *Towards Verifiable and Self-Correcting AI Physicists for Quantum Many-Body Simulations*, arXiv:2604.00149, separates programming verification from scientific/physical verification.

That is structurally consistent with the countermodel: extra semantic evidence can distinguish the worlds, but the semantics belong to the verifier/domain contract.

## F1 disposition

The monolithic candidate does not survive at the registered resolution. The surviving architecture is a **plural signal family + routing/materiality boundary**:

```text
native/domain/process/custody/data checks
        -> warning/evidence records
        -> responsibility/materiality assessment
        -> unresolved when decisive evidence is unavailable
```

Candidate terminal: `MULTIPLE_FAILURE_SIGNAL_ATOMS_REQUIRED`.

This terminal does **not** establish a new routing atom. Existing owners should be reused first:

- formal/physical/native verification -> P4/P8 and domain evaluators;
- execution/process drift -> existing execution/step-verification owners;
- evaluator/custody failure -> P4/P8;
- statistical/data integrity -> P1/P2/domain validation;
- causal responsibility/materiality -> #452/P6 responsibility.

# F2 — failure to scoped negative knowledge

## What the current V1 object actually does

`FailureKnowledge.v1` in #513 records an already-proposed scoped negative lesson:

- failed episode / attempt lineage;
- target contract and regime;
- responsibility-state lineage;
- excluded conditions;
- still-live alternatives;
- preserved successes;
- frozen applicability context;
- evidence and authority owner;
- conservative same/reopen coordinates.

It does **not** infer those exclusions from raw science and grants neither scientific refutation nor global prohibition.

That distinction is decisive. The scientific inference that a condition is actually excluded remains with the domain evidence/verifier and responsibility owner.

## Structural reduction

At the registered resolution, every non-digest field has an existing structural owner:

| `FailureKnowledge.v1` field | structural owner at this resolution |
| --- | --- |
| `failure_id` | episode/provenance identity |
| `target_contract_id` | typed ORION claim/contract identity |
| `regime_id` | ATMS context + P7 chart/regime identity |
| `attempted_trace_ids` | ordered episode provenance |
| `observed_failure_id` | evidence/provenance identity |
| `responsibility_state_id` | P6/#452 responsibility |
| `excluded_condition_ids` | TMS/ATMS nogood/conflict under assumptions |
| `still_live_alternative_ids` | non-nogood ATMS environments/alternatives |
| `preserved_success_ids` | justified unaffected nodes/results |
| `frozen_context` | ATMS assumption environment |
| `required_same_coordinates` | context predicates / compatibility gate |
| `reopen_on_change_coordinates` | P7 transport/reopen owner |
| `evidence_ids` | TMS justification + ORION provenance |
| `authority_owner_id` | P4/P8 external authority |

Doyle's TMS and de Kleer's ATMS already own reason/dependency maintenance and assumption-scoped inconsistent environments. CEGIS and related methods already own learning constraints from counterexamples inside registered spaces. ORION should therefore not rename the storage/composition of those structures as a new generic failure-extraction atom.

## Scope-extraction boundary

The reduction is deliberately **not** the claim

```text
FAIL -> automatically construct a correct nogood.
```

That would be circular and unsafe. The admissible flow is

```text
domain evidence / verifier
        + responsibility assessment
        + explicit scientific entailment or registered scope relation
        -> scoped conflict / negative conclusion
        -> FailureKnowledge.v1 interchange record
```

If the evidence does not warrant an exclusion, the correct result is no exclusion / unresolved. Repetition, confidence or natural-language severity cannot compensate.

## F2 disposition

Candidate terminal: `TMS_NOGOOD_PLUS_RESPONSIBILITY_SUFFICIENT`.

The scientific result is negative with respect to a **new generic extraction primitive**. `FailureKnowledge.v1` remains useful because it binds ORION's typed context, provenance and authority boundaries in one stable non-authorizing record.

# F3 — staleness and reopening

## V1 equality is intentionally conservative

#513's current `assess_failure_applicability()` has a simple policy:

- missing relevant context -> `UNRESOLVED`;
- changed `required_same` coordinate -> `NOT_APPLICABLE`;
- changed `reopen_on_change` coordinate -> `REOPENED`;
- exact compatible context -> `APPLIES`.

This is safe for a V1 transport-free substrate, but it is not a semantic theory of cross-regime persistence. In particular, a semantics-preserving rename/refactor can trigger reopening because the string coordinate changed.

That over-reopening is safer than silent negative transfer, but it is not the final answer to #518.

## P7 reduction

P7's formal core already distinguishes:

- evidence identity from obligation/closure semantics;
- representation change from latent-information change;
- partial maps from complete transport witnesses;
- complete support transport from incomplete target-ambiguous transport.

For a prior negative conclusion `z_neg`, treat the evidence, responsibility premises, scoped assumptions, target contract and defeater exclusions used by the conclusion as its support set.

A complete target transport must preserve the load-bearing semantics of that support. Then the old negative conclusion can be transported.

If transport is incomplete and two target completions remain compatible with all established mapping facts but disagree on whether `z_neg` remains valid, silent carry-forward is unsound. The system must reopen/revalidate or return `CANNOT_CHECK/UNRESOLVED`.

This is the same proof shape as P7's fail-closed closure transport; negative knowledge does not require a second transport calculus merely because the transported proposition is negative.

## Frozen cases

The finite packet checks:

1. unchanged identity context -> `APPLIES`;
2. semantics-preserving rename/refactor with complete witness -> `APPLIES`;
3. repaired measurement/evaluator with verified semantic change -> `REOPENED`;
4. changed objective / contract semantics -> `REOPENED`;
5. domain expansion with incomplete mapping -> `UNRESOLVED`;
6. missing representation mapping -> `UNRESOLVED`.

## F3 disposition

Candidate terminal: `P7_TRANSPORT_SUFFICIENT`.

`FailureKnowledge.v1` should therefore retain its conservative exact-context behavior as a cheap fail-closed path. A future consumer that wants to preserve an old negative lesson across a semantic regime change must present the same kind of complete transport evidence already owned by P7; it must not broaden V1 equality heuristics into a similarity guess.

# Consequences for the parent programmes

## #507 recursive atoms

These are the first three failure-side pilots using the common #513 packet, but they **do not by themselves close #507**. They demonstrate that the common study contract must support:

- formal non-identifiability/decomposition (`#516`);
- parent-formalism subsumption (`#517`);
- cross-owner reduction/transport subsumption (`#518`).

The parent still owes its broader #506 atom ownership map and the registered no-material-change saturation rounds before a #507 terminal is earned.

## #508 failure epistemology

The result simplifies the failure pipeline:

```text
failure occurs
-> specialized evidence makes it observable (or remains unresolved)
-> responsibility is assessed independently
-> a warranted scoped conflict can be recorded in FailureKnowledge.v1
-> unchanged contexts use the V1 fast path
-> semantic regime changes use P7 transport / reopen
```

#508 still owns the larger empirical/history programme; this packet does not satisfy the atlas, morphology, invented-world and transfer-efficacy obligations by itself.

## #513 implementation

No destructive rewrite is justified. Keep the V1 substrate because it is correctly non-authorizing and conservative. The F2 result narrows its scientific interpretation; the F3 result narrows its applicability semantics.

# Hostile nonclaims

This packet does not establish:

- a universal silent-failure detector;
- that specialized verifiers cover every scientific domain;
- that every failure yields a valid negative lesson;
- that TMS/ATMS can replace domain science or responsibility evidence;
- that a changed context always invalidates an old negative lesson;
- that similarity, version distance or LLM judgment is a semantic transport witness;
- protected downstream performance improvement;
- Jump competence, novelty or publication authority;
- #507 or #508 terminal closure.

The intended scientific contribution is **subtraction**: three plausible new atoms reduce to a smaller composition of existing owners plus explicit fail-closed boundaries.
