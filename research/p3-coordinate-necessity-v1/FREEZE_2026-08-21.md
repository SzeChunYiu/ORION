# Freeze: P3 coordinate-necessity atlas extension v1

**Frozen 2026-08-21, before any case was built, any arm was run, or any outcome
was observed.** Nothing below may be revised in response to a result. If a
result contradicts a prediction recorded here, the prediction is reported as
wrong and the construction stays as written.

Acting on `research/failures/2026-08-unapplied-treatment-vacuous-null/`.

## 1. What is being repaired, and what is not

Two of P3's six coordinate-ablation arms never applied their treatment.
`orion.study.p3_public_reference_analysis.ablated_relation` ablates by
`replace(projection, measurement_ids=())`, and on both frozen atlases
`measurement_ids` and `temporal_context_ids` are populated on **0 of 32** cases,
so that `replace` is the identity. Measured by
`python -m orion.study.p3.public_reference_audit`:

| arm | treated | decisions changed | verdict |
| --- | --- | --- | --- |
| `remove_referent` | 32 / 32 | 0 | FAIL — coordinate not load-bearing |
| `remove_construct` | 19 / 32 | 0 | FAIL — coordinate not load-bearing |
| `remove_measurement` | **0 / 32** | 0 | CANNOT_CHECK — treatment never applied |
| `remove_temporal_context` | **0 / 32** | 0 | CANNOT_CHECK — treatment never applied |
| `remove_modality_polarity_attribution_discourse` | 19 / 32 | 6 | PASS |
| `force_compatibility_without_obstruction` | 32 / 32 | 6 | PASS |

The defect is in the corpus, not the rule: `compare_meaning` reads both
coordinates, and a pair differing only on `measurement_ids` returns
`DISTINCT_MEASUREMENT` which ablates to `COMPATIBLE`, while a pair differing
only on `temporal_context_ids` returns `CONTEXTUAL_DIFFERENCE` which ablates to
`COMPATIBLE`.

**In scope:** give `remove_measurement` and `remove_temporal_context` a
denominator, by adding cases on which those two coordinates are populated and on
which the correct answer depends on them.

**Explicitly out of scope, and forbidden by this freeze:**

- Editing either frozen atlas, or any committed P3 result. Their `0 / 32`
  stands as the record. This extension is a **new** atlas with its own identity,
  built alongside them.
- Adding cases on which `referent_ids` or `construct_ids` *differ*. Those two
  arms currently report a real negative (removed, nothing moved). Adding cases
  engineered to flip them to `PASS` would be constructing the outcome. Every new
  case holds `referent_ids` and `construct_ids` **equal across the pair**, so
  those two arms gain treated cases and no opportunity to change a decision.
- Repairing the false-split comparator. `exact_coordinate_baseline` returns only
  `COMPATIBLE` or `UNRESOLVED`; it has no branch that separates, so no corpus can
  give it a false-split opportunity. That is a comparator-design defect, reported
  as such, not fixed here.
- Adding gold-`UNRESOLVED` cases. Also named in the failure record's correct
  response; also not this repair, and adding them would move the abstention
  denominator at the same time as the coordinate one, confounding both.

## 2. Identity of the new artifact

| field | value |
| --- | --- |
| atlas id | `coordinate-necessity-v1` |
| protocol id | `P3.coordinate-necessity-extension.v1` |
| location | `research/p3-coordinate-necessity-v1/` |
| cases file | `research/p3-coordinate-necessity-v1/cases.jsonl` |
| builder | `src/orion/study/p3_coordinate_necessity_build.py` |
| parent atlas | `papers/orion-13-global-knowledge-portrait/gold/adjudicated/public-reference-v1.1-confirmatory/PUBLIC_REFERENCE_GOLD_V1.jsonl` (32 cases, copied byte-identical, never modified) |
| case schema | unchanged: `orion.p3.public-reference-case.v1` |

The atlas is the parent's 32 cases **plus** 24 newly constructed cases, emitted
in `case_id` sort order, one canonical JSON object per line. Its `cases_hash` is
the SHA-256 of those bytes and is recorded in `BUILD_REPORT.json` together with
the SHA-256 of the parent file it was extended from.

Carrying the parent's 32 cases forward is what makes the before/after table in
§7 readable: every arm is measured on *the same 32 cases plus the new 24*, so a
change in any arm's counts is attributable to the added cases alone.

### 2.1 The new cases are synthetic, and the artifact says so

The 24 added cases are **not** public-reference cases. The upstream corpora the
v1.1 builder draws on (MUSE, SciFact, SciSchema) are not present in this
environment, and none of them supplies a pair that differs only on a measurement
or temporal coordinate. The added cases are generated by code from a frozen
standard table shipped beside the atlas
(`SYNTHETIC_COORDINATE_STANDARD.json`), and their gold follows from that table
by a stated deterministic rule.

Consequence, to be stated wherever this atlas is cited: it can establish that a
coordinate is **load-bearing in the rule** — that removing it moves decisions on
cases whose answer depends on it. It cannot establish that such cases are
**frequent in public scientific corpora**. The `BUILD_REPORT.json` carries
`synthetic_case_count` and an `external_validity` note saying exactly this, and
the atlas may not be substituted for the public-reference atlas in any external
validity claim.

## 3. Construction of the 24 new cases

Fixed before building. Counts, fields and gold rules are all given here.

### 3.1 Two strata, 12 cases each

**Stratum A — measurement.** `case_family = "same_construct_different_measurement"`.
Twelve pairs. Both projections carry a populated `measurement_ids` of arity 1.

- slots 0–3 (**A-differ**, 4 cases): the two `measurement_ids` name **different**
  dimension classes of the frozen table → gold `DISTINCT_MEASUREMENT`.
- slots 4–11 (**A-same**, 8 cases): the two `measurement_ids` are **equal** →
  gold `COMPATIBLE`.

**Stratum B — temporal context.** `case_family = "same_entity_different_temporal_state"`.
Twelve pairs. Both projections carry a populated `temporal_context_ids` of arity 1.

- slots 0–3 (**B-differ**, 4 cases): the two `temporal_context_ids` name
  **different**, disjoint observation epochs of the frozen table → gold
  `CONTEXTUAL_DIFFERENCE`.
- slots 4–11 (**B-same**, 8 cases): the two `temporal_context_ids` are **equal**
  → gold `COMPATIBLE`.

Every case in both strata populates **all four** coordinate tuples
(`referent_ids`, `construct_ids`, `measurement_ids`, `temporal_context_ids`) at
arity 1 on both sides. In stratum A the temporal coordinate is populated and
equal; in stratum B the measurement coordinate is populated and equal. The
predicate is equal across the pair in every case (an unequal predicate returns
`UNRESOLVED` before any coordinate is read). `polarity = POSITIVE` and
`modality = ASSERTED` on both sides of every case; `attribution_id` and
`discourse_relation` are empty on both sides.

New-case totals: 24 cases — 16 `COMPATIBLE`, 4 `DISTINCT_MEASUREMENT`,
4 `CONTEXTUAL_DIFFERENCE`.
Extended-atlas totals: 56 cases — 42 `COMPATIBLE`, 6 `CONTRADICTORY`,
4 `DISTINCT_MEASUREMENT`, 4 `CONTEXTUAL_DIFFERENCE`.

The 8:4 same-to-differ ratio inside each stratum is fixed here, before the
identifiability audit is run, for the reason given in §5.3: it keeps
`COMPATIBLE` the strict majority inside every construction-cue cell, which is
the property that stops a construction cue from recovering the answer.

### 3.2 What makes a case's answer *depend* on the coordinate

A case's answer depends on coordinate *c* iff **both**:

1. `compare_meaning(left, right)` equals the case's gold relation — the full
   system is right on it; and
2. `compare_meaning(ablate_c(left), ablate_c(right))` **differs from that gold
   relation** — emptying *c* makes the full system wrong on it.

For A-differ, (1) is `DISTINCT_MEASUREMENT` and (2) is `COMPATIBLE`. For
B-differ, (1) is `CONTEXTUAL_DIFFERENCE` and (2) is `COMPATIBLE`. The builder
**asserts both conditions on every differ case at build time** and refuses to
emit an atlas where any differ case fails them; an extension that did not
actually create the dependence would repeat the failure it is repairing at one
remove.

A-same and B-same cases are *treated* by the arm (a populated coordinate becomes
empty, so the input genuinely changes) but their decision does not move. They
are the honest denominator: cases where the coordinate was present, was removed,
and the answer legitimately survived.

### 3.3 Gold authority and provenance

`expected.authority.kind = "DERIVED_FROM_ALLOWED"` on all 24, with a single
derivation rule shared by every new case, differ and same alike:

    identity:frozen-coordinate-standard-distinctness

stated in full as: *two projections that agree on every exposed coordinate are
`COMPATIBLE`; two that agree on referent and construct and name distinct
measurement-dimension classes of the frozen standard are `DISTINCT_MEASUREMENT`;
two that agree on referent, construct and measurement and name distinct,
disjoint observation epochs of the frozen standard are `CONTEXTUAL_DIFFERENCE`.*

One rule string for all 24 cases is deliberate: a derivation rule that named the
answer per sub-stratum would be a construction cue printed inside the gold
record.

`source_records` is one record on every new case, naming the emitted standard
file, with `revision` and `content_hash` both the SHA-256 of that file's bytes.
No upstream text is vendored. `evidence` is two locators (left side, right side)
on every new case.

### 3.4 Everything a case carries that is not a coordinate is shape-invariant

Fixed before building, so that no construction-level feature separates a differ
case from a same case:

- `case_id` = `coordinate-synth-` + 16 hex characters of a content hash. Same
  length, same separator count, same alphabetic prefix on all 24.
- `projection_id`, `source_id`, `source_span` are fixed-width templates,
  identical in length on every new case and on both sides. (The comparison rule
  provably ignores all three: `exact_coordinate_baseline` excludes them and
  `compare_meaning` never reads them.)
- `discipline` cycles `biology, chemistry, materials, physics` by slot index
  within each stratum, so each discipline carries exactly one differ case and
  two same cases per stratum. No discipline is unique to a label.
- one `source_records` entry, one `dataset` name, one `authority.kind`, two
  `evidence` entries — the same on all 24.
- all four coordinate arities are `1` on both sides of all 24, so coordinate
  cardinality and coordinate missingness are constant across the new cases.

The only thing that varies with the answer is the coordinate *values*, and
reading those is the competence under test, not a shortcut.

## 5. Identifiability check, decided in advance

The P4 lane's record (`research/failures/2026-08-label-recoverable-from-construction-cue/`)
is that a well-intentioned repair shipped a new cue: after `len(evidence) == 0`
was closed, `len(evidence[0]["content"])` recovered the same label at
informedness 1.0. A repair that populates two coordinates on 24 constructed
cases is exactly the shape of change that can do this again.

### 5.1 Instrument and ceiling

`orion.programme.benchmark_identifiability.audit_label_identifiability`, one
audit per gold relation present in the corpus (one-vs-rest), with
`max_recovery = 0.0` — the strict reading: no competence-free cue may separate
the label at all.

### 5.2 Splits, and why the primary one is in-sample

Two split modes, both declared here, both reported:

- **Primary — in-sample.** Every case is entered twice, once as `FIT` and once
  as `EVAL`. The probe's majority-vote lookup is fitted on the very cases it is
  scored on. This upper-bounds recoverability: a cue that cannot separate the
  label even when allowed to memorise the cases it is graded on cannot separate
  it out of sample either. It also removes split-sampling noise, which a 56-case
  corpus cannot absorb.
- **Secondary — hash parity.** `FIT` iff `int(sha256(case_id), 16)` is even,
  `EVAL` otherwise. Reported alongside; the in-sample number governs.

### 5.3 Three corpora, so a leak can be attributed

The audit runs on all three, and the comparison is the point:

- the parent atlas alone (32 inherited cases),
- the new cases alone (24 constructed cases),
- the extended atlas (56).

A leak present in the parent and in the extension is inherited. A leak present
in the new cases, or in the extension but not the parent, was **shipped by this
repair** and is reported as such in those words.

### 5.4 Probes, declared before any is run

Every probe reads construction, never coordinate values. Coordinate values are
the input the system is supposed to read; reading them is the task, not a cue.

| probe id | kind | cues |
| --- | --- | --- |
| `case_id_shape` | IDENTIFIER_SHAPE | length of `case_id`, its `-` count, its alphabetic prefix before the first digit |
| `case_family` | ENUM_VALUE | the `case_family` token |
| `discipline` | ENUM_VALUE | the `discipline` token |
| `source_provenance` | COUNT | number of `source_records`, sorted tuple of their `dataset` names |
| `gold_authority_stamp` | ENUM_VALUE | `expected.authority.kind`, whether a `derivation` is present, number of `evidence` entries |
| `coordinate_arity` | COUNT | the eight tuple lengths (`referent`, `construct`, `measurement`, `temporal` × left, right) — lengths only, values never read |
| `coordinate_missingness` | FIELD_MISSINGNESS | the eight booleans "is this tuple empty" |
| `identifier_string_shape` | STRING_SHAPE | lengths of both `projection_id`s and both `source_span`s |
| `ordinal_quartile` | ORDINAL_POSITION | which quartile of the emitted order the case sits in |

No probe reads a hash value, an id's characters, or a coordinate id. A probe
that reads a high-cardinality opaque value would, under the in-sample split,
memorise the corpus and report a leak that is an artifact of the probe.

### 5.5 What the outcomes mean

- **PASS on all three corpora** — no declared construction cue separates any gold
  relation. Reported as: the repair did not ship a cue that this probe set can
  see. Not as: the atlas has no cues.
- **FAIL on the new cases or on the extension but not the parent** — this repair
  shipped a cue. Reported in those words, with the probe and its informedness.
  The atlas is then not fit to carry the arm result, and the report says so.
- **FAIL on all three** — inherited from the parent atlas; reported as a
  pre-existing property of the frozen corpus, with its informedness.
- **CANNOT_CHECK** — reported as an absent audit, never as a clean one.
